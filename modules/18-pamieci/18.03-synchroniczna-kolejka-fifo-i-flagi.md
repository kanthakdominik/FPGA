## Po co to jest

Kolejka FIFO to najczęściej używana struktura z pamięcią w FPGA: wyrównuje różnice tempa między producentem i konsumentem, buforuje paczki danych, łączy bloki z różną latencją i rozdziela potoki. W module 13 powstało małe FIFO jako obiekt weryfikacji formalnej ([13.04](../13-weryfikacja-formalna/13.04-formalna-weryfikacja-fifo-i-interfejsow-z.md)), w module 15 — kolejka asynchroniczna ([15.05](../15-zegary-reset-cdc/15.05-asynchroniczna-kolejka-fifo.md)). Tutaj FIFO w wersji produkcyjnej: zbudowane na bloku pamięci (odczyt synchroniczny), z licznikiem zajętości, flagami „prawie pełna/pusta” i trybem z wyprzedzeniem (*first-word fall-through*, FWFT), który wymaga dodatkowej logiki właśnie dlatego, że pamięć blokowa ma odczyt z rejestrem.

## Intuicja

Taśma w kasie sklepowej: klient dokłada zakupy z jednej strony, kasjerka zdejmuje z drugiej. W trybie standardowym kasjerka mówi „następny” i dopiero wtedy produkt przyjeżdża; w trybie FWFT następny produkt zawsze już leży pod ręką — zdjęcie go od razu podsuwa kolejny. Flagi „prawie pełna” to tablica „zaraz zabraknie miejsca”, wystawiana z wyprzedzeniem, żeby klient zdążył przestać dokładać.

## Teoria

### Budowa

- pamięć 2^AW słów; wskaźniki zapisu i odczytu (AW bitów, zawijają się),
- **licznik słów w pamięci** `n_mem` (AW + 1 bitów) zamiast porównywania wskaźników — jedna domena zegarowa, więc licznik jest prosty: +1 przy zapisie, −1 przy odczycie, bez zmian, gdy oba naraz,
- `full = (n_mem == 2^AW)`, pusta — `n_mem == 0`; zapis przy `full` i odczyt przy `empty` są ignorowane (ochrona w kolejce, nie u użytkownika),
- odczyt pamięci synchroniczny: `dout <= mem[rd_ptr]` — wzorzec bloku RAM ([18.01](18.01-bloki-pamieci-tryby-jedno-i-dwuportowe-odczyt.md)). Odczyt i zapis tego samego adresu w jednym takcie nie występuje: odczyt wymaga niepustej kolejki, a wtedy wskaźniki są różne (równe są tylko przy pustej albo pełnej, a przy pełnej zapis jest zablokowany).

### Tryb standardowy i FWFT

| | Standardowy (`FWFT = 0`) | FWFT (`FWFT = 1`) |
|---|---|---|
| `dout` | dana pojawia się takt po `rd_en` | najstarsza dana czeka na wyjściu, gdy `empty = 0` |
| `rd_en` | „daj następną” | „zabrałem tę” (potwierdzenie) |
| `empty` | pamięć pusta | rejestr wyjściowy pusty |
| latencja zapis → wyjście | zapis, potem `rd_en`, dana po takcie | 2 takty od zapisu do pustej kolejki |
| pojemność | 2^AW | 2^AW + 1 (słowo w rejestrze wyjściowym) |
| interfejs pasuje do | prostego odbiorcy, który sam steruje odczytem | strumieni `valid`/`ready` (`valid = !empty`, `ready = rd_en`) |

FWFT na pamięci z odczytem synchronicznym: rejestr wyjściowy pamięci (`dout`) staje się stopniem wyprzedzenia z flagą `valid`. Odczyt z pamięci następuje, gdy pamięć nie jest pusta i rejestr jest wolny albo właśnie zwalniany (`!valid || rd_en`) — pełna przepustowość, słowo w każdym takcie.

### Flagi programowalne

- `almost_full = count ≥ AF` — producent z opóźnieniem reakcji (potok, transmisja przez łącze, zapis paczkami) musi przestać, zanim kolejka się zapełni: AF = głębokość − (opóźnienie reakcji w słowach),
- `almost_empty = count ≤ AE` — konsument paczkowy zaczyna dopiero, gdy jest co najmniej AE + 1 słów,
- `count` — liczba słów dostępnych (w FWFT łącznie z rejestrem wyjściowym).

Flagi liczone z rejestrów (licznik) i porównań ze stałymi — kilka LUT, bez długich ścieżek.

### FIFO w narzędziach

`scfifo` (Quartus) i FIFO Generator / `xpm_fifo_sync` (Vivado) robią to samo z opcjami: tryb *show-ahead*, rejestr wyjściowy, `usedw`, flagi programowalne, ochrona przed przepełnieniem. Własne FIFO opłaca się, gdy trzeba przenośności między producentami albo nietypowych flag; IP — gdy liczą się przetestowane szczegóły i duże głębokości z wieloma blokami.

## Schemat i przebiegi

```
 wr_en, din ─► [ pamięć 2^AW ] ─► dout (rejestr)          FWFT: dout + valid = stopień wyprzedzenia
                wr_ptr  rd_ptr
 n_mem: +1 zapis, −1 odczyt ─► full, empty, count ─► almost_full (≥ AF), almost_empty (≤ AE)

 FWFT, zapis do pustej kolejki:
 takt     0     1     2     3
 wr_en    ▔▔▔▔▔▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
 din      A
 n_mem    0     1     0
 empty    ▔▔▔▔▔▔▔▔▔▔▔╲▁▁▁▁▁▁▁▁   dane na wyjściu 2 takty po zapisie
 dout                 A
```

## Kod: VHDL

[hdl/vhdl/fifo_bram.vhd](hdl/vhdl/fifo_bram.vhd) — gałąź FWFT:

```vhdl
g_fwft : if FWFT generate
  do_rd <= (not mem_empty) and ((not valid) or rd_en);
  empty <= not valid;
  cnt   <= resize(n_mem, AW + 2) + 1 when valid = '1' else resize(n_mem, AW + 2);
  ...
      elsif do_rd = '1' then
        valid <= '1';
      elsif rd_en = '1' then
        valid <= '0';
```

## Kod: Verilog

[hdl/verilog/fifo_bram.v](hdl/verilog/fifo_bram.v) — pamięć, wskaźniki i licznik:

```verilog
always @(posedge clk) begin
    if (do_wr) mem[wr_ptr] <= din;
    if (do_rd) dout <= mem[rd_ptr];
end
...
if (do_wr) wr_ptr <= wr_ptr + 1'b1;
if (do_rd) rd_ptr <= rd_ptr + 1'b1;
n_mem <= n_mem + {{AW{1'b0}}, do_wr} - {{AW{1'b0}}, do_rd};
```

## Kod: SystemVerilog

[hdl/sv/fifo_bram.sv](hdl/sv/fifo_bram.sv) — flagi:

```systemverilog
assign mem_empty    = (n_mem == '0);
assign full         = (n_mem == PELNA);
assign do_wr        = wr_en && !full;
assign almost_full  = (count >= (AW+2)'(AF));
assign almost_empty = (count <= (AW+2)'(AE));
```

## Co powstaje po syntezie

Yosys `synth_ecp5` dla `fifo_bram` 512 × 8 z FWFT: jeden blok DP16KD, 56 przerzutników i 54 LUT4 ([wnioskowanie.py](pamieci/wnioskowanie.py), [18.01](18.01-bloki-pamieci-tryby-jedno-i-dwuportowe-odczyt.md)). Przerzutniki to wskaźniki, licznik, flaga ważności i rejestry, które narzędzie dodało przy mapowaniu na blok; LUT — sumatory i porównania flag. Pamięć 4096 bitów nie zajęła ani jednego przerzutnika. W syntezie ogólnej (`synth`, bez bloków RAM) kolejka z parametrami domyślnymi to 149 przerzutników i 149 LUT4 — pamięć w rejestrach.

## Weryfikacja

`tb_fifo_bram` (3 języki) — PASS: wersja standardowa i FWFT na tym samym pobudzeniu, 6000 taktów w trzech fazach (80/20, 20/80, 50/50 zapisów do odczytów), model kolejki w testbenchu. Sprawdzane w każdym takcie: dane i ich kolejność, `count`, `empty`, `full` (w FWFT — dopiero po zapełnieniu pamięci), obie flagi `almost_*` względem `count`, ignorowanie zapisu przy pełnej. Pokrycie: `full`, `empty`, `almost_full`, `almost_empty` osiągnięte, zapisy odrzucone.

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| Jedna domena: licznik słów (AW + 1 bitów) zamiast porównania wskaźników | FIFO synchroniczne |
| Zapis przy full i odczyt przy empty ignorowane w kolejce | ochrona |
| Standard: dana takt po `rd_en`; FWFT: dana czeka, `rd_en` = potwierdzenie | wybór trybu |
| FWFT na bloku RAM: rejestr wyjściowy pamięci + flaga valid, pojemność 2^AW + 1 | implementacja |
| AF = głębokość − opóźnienie reakcji producenta (w słowach) | dobór flag |
| Flagi z licznika i porównań ze stałymi — krótkie ścieżki | timing |
| `valid = !empty`, `ready = rd_en` — FWFT jako interfejs strumieniowy | łączenie bloków |

## Typowe pułapki

- **Tryb standardowy podłączony jak FWFT** (albo odwrotnie) — odbiorca bierze daną o takt za wcześnie: pierwsze słowo śmieciowe, ostatnie gubione.
- **`full` liczone z `wr_ptr == rd_ptr`** bez dodatkowego bitu — pełna i pusta nierozróżnialne.
- **Zapis przy full bez blokady** — nadpisanie najstarszego słowa i rozjechany licznik.
- **almost_full za późno** — producent z potokiem trzech taktów wciąż zapisuje po zapaleniu flagi, a próg ustawiono na głębokość − 1.
- **Odczyt asynchroniczny pamięci** (`assign dout = mem[rd_ptr]`) „dla prostoty FWFT” — pamięć w LUT/przerzutnikach zamiast bloku RAM.
- **Reset tylko wskaźników, bez licznika** (albo odwrotnie) — kolejka po resecie twierdzi, że ma dane.

## Pytania rekrutacyjne

1. **Czym różni się FIFO w trybie standardowym od FWFT i jak zbudować FWFT na pamięci blokowej?**

<details>
<summary>Odpowiedź</summary>

W standardowym dana pojawia się na wyjściu takt po `rd_en`; w FWFT najstarsza dana już czeka na wyjściu, gdy kolejka nie jest pusta, a `rd_en` ją zdejmuje. Pamięć blokowa ma odczyt synchroniczny, więc FWFT wymaga stopnia wyprzedzenia: rejestr wyjściowy z flagą ważności, ładowany z pamięci, gdy jest pusty albo właśnie zwalniany (`!valid || rd_en`) i pamięć ma dane. `empty = !valid`; pojemność rośnie o jedno słowo; dane pojawiają się na wyjściu 2 takty po zapisie do pustej kolejki.
</details>

2. **Jak liczysz flagi pełna/pusta w FIFO synchronicznym?**

<details>
<summary>Odpowiedź</summary>

Albo licznikiem słów (AW + 1 bitów: +1 przy zapisie, −1 przy odczycie) — pełna przy 2^AW, pusta przy 0 — albo wskaźnikami o jeden bit szerszymi niż adres: równe — pusta, różne tylko najstarszym bitem — pełna. W jednej domenie zegarowej oba sposoby są proste; licznik daje od razu `count` i flagi programowalne.
</details>

3. **Do czego służy almost_full i jak dobrać próg?**

<details>
<summary>Odpowiedź</summary>

Do zatrzymania producenta, który nie reaguje natychmiast — ma potok, wysyła paczkami albo sygnał wstrzymania dochodzi do niego z opóźnieniem. Próg = głębokość minus maksymalna liczba słów, które producent może jeszcze wysłać po zapaleniu flagi (opóźnienie reakcji w taktach × słowa na takt, plus paczka w toku). Za wysoki próg — przepełnienie; za niski — niewykorzystana głębokość.
</details>

## Zadania

1. Dodaj do `fifo_bram` flagi lepkie `overflow` i `underflow` (próba zapisu przy pełnej / odczytu przy pustej) kasowane resetem. **Kryterium zaliczenia:** test, w którym obie flagi ustawiają się dokładnie przy pierwszej takiej próbie.

2. Zbuduj adapter strumieniowy: wejście `valid`/`ready`, wyjście `valid`/`ready`, w środku `fifo_bram` z FWFT. **Kryterium zaliczenia:** test z losowym `ready` odbiorcy — wszystkie dane bez zgubienia i duplikatu, przepustowość 1 słowo/takt przy `ready = 1`.

3. Porównaj w Yosysie (`synth_ecp5`) `fifo_bram` 512 × 8 z FWFT i bez. **Kryterium zaliczenia:** liczba przerzutników i LUT obu wersji i wyjaśnienie różnicy.
