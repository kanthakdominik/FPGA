## Po co to jest

Tablice stałych są wszędzie: próbki sinusa dla generatora DDS, współczynniki filtrów, czcionki znaków dla wyświetlacza, tablice gamma i korekcji, mikrokod automatu, program startowy procesora. Bloki pamięci FPGA można wypełnić w chwili konfiguracji — zawartość jest częścią strumienia konfiguracyjnego, więc „ROM” to po prostu blok RAM bez portu zapisu. Kłopot w tym, że **każde narzędzie czyta pliki inicjalizacji inaczej**: Quartus woli `.mif`, Vivado `.mem`, symulatory `$readmemh`, a VHDL nie ma standardowej funkcji wczytania pliku do pamięci w syntezie. Ten temat pokazuje jeden plik źródłowy w trzech formatach i przenośny sposób jego użycia w trzech językach.

## Intuicja

Płyta z nagraniem: zawartość wytłoczono przy produkcji, odtwarzacz tylko czyta. W FPGA „tłocznią” jest konfiguracja — wystarczy, że narzędzie zrozumie, z jakiego pliku tłoczyć.

## Teoria

### Formaty plików

| Format | Kto czyta | Postać |
|---|---|---|
| `.hex` dla `$readmemh` | Icarus, Verilator, Questa, Quartus, Vivado, Yosys | jedna wartość szesnastkowa na wiersz (lub kilka rozdzielonych spacjami), opcjonalnie `@adres`, komentarze `//` |
| `.mem` | Vivado (`$readmemh`, edytor IP), Yosys | to samo co wyżej, zwyczajowo z `@0` |
| `.mif` | Quartus (atrybut `ram_init_file`, IP RAM/ROM, edytor *In-System Memory Content Editor*) | nagłówek `WIDTH`, `DEPTH`, `ADDRESS_RADIX`, `DATA_RADIX`, potem `CONTENT BEGIN … adres : wartość; … END;` |
| Intel HEX (`.hex` z rekordami `:`) | Quartus (IP), programatory, kompilatory C | rekordy z sumą kontrolną — **inny format niż `.hex` dla `$readmemh`**, mimo tego samego rozszerzenia |
| `.coe` | Vivado (Block Memory Generator) | `memory_initialization_radix`, `memory_initialization_vector` |

Najlepiej generować wszystkie formaty jednym skryptem z jednego źródła — tu [hdl/dane/gen_sinus.py](hdl/dane/gen_sinus.py) zapisuje `sinus.hex`, `sinus.mem` i `sinus.mif` (256 próbek, wartość = round(127,5 + 127,5 · sin(2πk/256)): k = 0 → 0x80, k = 64 → 0xFF).

### Verilog i SystemVerilog

`initial $readmemh(PLIK, rom);` w module z pamięcią — standard IEEE 1364, rozumiany przez symulatory i przez syntezę we wszystkich głównych narzędziach. Ścieżka pliku jest względna do **katalogu roboczego narzędzia** (katalog symulacji, katalog projektu Quartusa), nie do pliku źródłowego — stąd parametr `PLIK` ustawiany z góry (w projekcie DECA: `../../hdl/dane/sinus.hex`).

### VHDL

VHDL nie ma `$readmemh`. Dwie drogi:

1. **Funkcja nieczysta czytająca plik przez `textio`** wywołana w wartości początkowej sygnału: `signal rom : rom_t := wczytaj(PLIK);`. Działa w GHDL, Questa, Vivado. Quartus Standard (wersja dla MAX 10) nie czyta plików w czasie syntezy, więc w projekcie dla niego `PLIK => ""` (funkcja zwraca zera) i…
2. **Atrybut `ram_init_file`** na sygnale pamięci z nazwą pliku `.mif` — Quartus wypełnia blok z tego pliku, inne narzędzia atrybut ignorują.

Moduł `rom_sinus.vhd` ma oba generyki (`PLIK` i `PLIK_MIF`), więc jeden kod służy symulacji i Quartusowi. Trzecia, całkowicie przenośna droga: skrypt generuje **pakiet VHDL ze stałą** (`constant SINUS : rom_t := (x"80", x"83", …)`) — zero plików w czasie syntezy, ale duże tablice dają długie źródła.

### ROM w bloku czy w logice?

ROM z odczytem synchronicznym może trafić do bloku pamięci, ale narzędzie wybiera tańszą realizację: Yosys dla ECP5 zmapował ROM 256 × 8 na **98 LUT4** zamiast bloku 18 kbit ([wnioskowanie.py](pamieci/wnioskowanie.py)). Atrybut wymusza wybór: `(* rom_style = "block" *)` (Yosys, Vivado), `(* romstyle = "M9K" *)` (Quartus); odwrotnie — `"logic"`/`"distributed"`. Quartus ma też opcję *Auto ROM Replacement*. Duże ROM-y (dziesiątki kbit) zawsze trafiają do bloków.

### Inicjalizacja RAM

Ten sam mechanizm działa dla RAM: blok zaczyna pracę z zawartością z pliku, a potem jest normalnie zapisywany. Uwaga: zawartość jest ładowana **tylko przy konfiguracji** — reset logiki jej nie przywraca ([18.01](18.01-bloki-pamieci-tryby-jedno-i-dwuportowe-odczyt.md)). Quartus pozwala też podmienić zawartość bez ponownej kompilacji: *Update Memory Initialization File* + ponowne *Assembler* (sam `.sof`), a w działającym układzie — *In-System Memory Content Editor* przez JTAG.

## Schemat i przebiegi

```
 gen_sinus.py ──► sinus.hex ──► $readmemh (Verilog/SV: symulacja + synteza), textio (VHDL: symulacja)
              ├─► sinus.mem ──► Vivado / Yosys
              └─► sinus.mif ──► Quartus: ram_init_file (VHDL), IP ROM, edytor pamięci

 rom_sinus:  clk ─► addr ─► [ROM 256 × 8] ─► dout (takt później, gdy en = 1)
```

## Kod: VHDL

[hdl/vhdl/rom_sinus.vhd](hdl/vhdl/rom_sinus.vhd) — funkcja `textio` i atrybut dla Quartusa:

```vhdl
impure function wczytaj(nazwa : string) return rom_t is
  file f       : text;
  variable st  : file_open_status;
  variable l   : line;
  variable v   : std_logic_vector(((W + 3) / 4) * 4 - 1 downto 0);
  variable r   : rom_t := (others => (others => '0'));
begin
  if nazwa'length = 0 then
    return r;                                   -- Quartus: zawartość z .mif
  end if;
  file_open(st, f, nazwa, read_mode);
  for i in rom_t'range loop
    exit when endfile(f);
    readline(f, l);
    hread(l, v);
    r(i) := v(W - 1 downto 0);
  end loop;
  file_close(f);
  return r;
end function;

signal rom : rom_t := wczytaj(PLIK);
attribute ram_init_file : string;
attribute ram_init_file of rom : signal is PLIK_MIF;
```

## Kod: Verilog

[hdl/verilog/rom_sinus.v](hdl/verilog/rom_sinus.v):

```verilog
reg [W-1:0] rom [0:(1<<AW)-1];
initial $readmemh(PLIK, rom);

always @(posedge clk)
    if (en) dout <= rom[addr];
```

## Kod: SystemVerilog

[hdl/sv/rom_sinus.sv](hdl/sv/rom_sinus.sv) — to samo z `logic` i `always_ff`; wymuszenie bloku w [pamieci/rom_blok.v](pamieci/rom_blok.v):

```verilog
(* rom_style = "block", romstyle = "M9K" *)
reg [W-1:0] rom [0:(1<<AW)-1];
initial $readmemh(PLIK, rom);
```

## Co powstaje po syntezie

Yosys `synth_ecp5`: `rom_sinus` 256 × 8 — 0 bloków DP16KD, 98 LUT4 i 8 przerzutników (rejestr wyjściowy); ten sam ROM z `rom_style = "block"` — jeden DP16KD (wynik w podsumowaniu CI). W syntezie ogólnej (`synth`, bez bloków) 161 LUT4 i 8 FF. W Quartusie projekt DECA powinien pokazać ROM w jednym bloku M9K z plikiem `sinus.mif`/`sinus.hex` w raporcie *RAM Summary* (`make raporty`).

## Weryfikacja

`tb_rom_sinus` (3 języki) — PASS: wszystkie 256 adresów porównane z sinusem liczonym w testbenchu (`$sin` w Verilogu/SV, `math_real.sin` w VHDL) z tolerancją ±1 (zaokrąglenie); próbki charakterystyczne: k = 0 → 128, k = 64 → 255; przy `en = 0` wyjście się nie zmienia. Test sprawdza więc i plik, i wczytanie, i odczyt synchroniczny.

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| `initial $readmemh(PLIK, mem)` — przenośne w symulacji i syntezie | Verilog/SV |
| Ścieżka pliku względem katalogu roboczego narzędzia | wszystkie narzędzia |
| VHDL: textio w funkcji (symulacja, Vivado) + `ram_init_file` z `.mif` (Quartus) | VHDL |
| `.hex` dla `$readmemh` ≠ Intel HEX z rekordami `:` | formaty |
| Jeden skrypt generuje wszystkie formaty z jednego źródła | utrzymanie |
| Mała ROM może trafić do LUT; `rom_style`/`romstyle` wymusza blok | wnioskowanie |
| Zawartość ładowana tylko przy konfiguracji, reset jej nie przywraca | RAM z inicjalizacją |

## Typowe pułapki

- **Plik nie znaleziony** — w Verilogu `$readmemh` daje tylko ostrzeżenie, a pamięć zostaje X (symulacja) lub zera (synteza); zawsze sprawdzaj raport syntezy i dodaj test zawartości.
- **Intel HEX zamiast prostego `.hex`** — `$readmemh` nie rozumie rekordów `:`, Quartus odwrotnie: rozszerzenie nie mówi, który to format.
- **Mniej wierszy niż głębokość** — reszta pamięci niezainicjalizowana; `.mif` z `DEPTH` innym niż pamięć — ostrzeżenie i obcięcie.
- **VHDL z textio w Quartusie** — synteza nie wczyta pliku; ROM wypełniony zerami albo błąd elaboracji, gdy `assert` wymaga pliku.
- **Edycja `.mif` bez *Update Memory Initialization File*** — stary `.sof` ma starą zawartość.
- **ROM z odczytem asynchronicznym** (`assign dout = rom[addr]`) — zawsze logika, nigdy blok; przy dużych tablicach tysiące LUT.

## Pytania rekrutacyjne

1. **Jak przenośnie zainicjalizować pamięć w Verilogu i w VHDL?**

<details>
<summary>Odpowiedź</summary>

W Verilogu/SV: `initial $readmemh("plik.hex", mem);` — rozumieją to symulatory i syntezatory Quartus, Vivado, Yosys. W VHDL: funkcja nieczysta czytająca plik przez `textio` w wartości początkowej sygnału pamięci (symulacja, Vivado), a dla Quartusa dodatkowo atrybut `ram_init_file` z plikiem `.mif`; całkowicie przenośnie — pakiet ze stałą tablicą generowany skryptem. Pliki w różnych formatach generuje jeden skrypt z jednego źródła.
</details>

2. **Czy ROM zawsze trafia do bloku pamięci?**

<details>
<summary>Odpowiedź</summary>

Nie. ROM z odczytem synchronicznym może trafić do bloku, ale narzędzie wybiera realizację tańszą według swojego modelu kosztów: mała tablica (np. 256 × 8) bywa tańsza w LUT niż zajęcie całego bloku. ROM z odczytem asynchronicznym zawsze jest logiką. Wybór wymusza atrybut (`romstyle = "M9K"` w Quartusie, `rom_style = "block"` w Vivado i Yosysie) albo ustawienie narzędzia.
</details>

3. **Zmieniłeś tablicę współczynników w pliku .mif. Czy musisz ponownie kompilować projekt?**

<details>
<summary>Odpowiedź</summary>

W Quartusie nie: *Update Memory Initialization File* wczytuje nową zawartość do bazy projektu, a ponowny Assembler generuje `.sof` w kilkadziesiąt sekund, bez syntezy i dopasowania. Na działającym układzie można też podmienić zawartość przez JTAG (*In-System Memory Content Editor*), jeśli pamięć ma włączony identyfikator do edycji. Zawartość pliku nie wpływa na rozmieszczenie ani timing.
</details>

## Zadania

1. Zamień ROM sinusa na ćwierć okresu (64 próbki) i odtwarzaj pełny okres przez odbicia adresu i znaku. **Kryterium zaliczenia:** test porównujący wynik z pełną tablicą dla wszystkich 256 faz (±1).

2. Dopisz do `gen_sinus.py` generowanie pakietu VHDL ze stałą i wersję `rom_sinus` bez textio. **Kryterium zaliczenia:** `tb_rom_sinus.vhd` przechodzi z nową wersją, a moduł nie używa `std.textio`.

3. Dodaj do `wnioskowanie.py` ROM 1024 × 16 bez atrybutu. **Kryterium zaliczenia:** sprawdź, od jakiej wielkości Yosys sam wybiera blok, i zapisz wniosek.
