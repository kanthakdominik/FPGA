## Po co to jest

Dźwięk w systemach cyfrowych płynie między układami przez **I²S** (albo jego odmiany: left-justified, TDM/DSP): trzy przewody, ciągły strumień próbek stereo w rytmie częstotliwości próbkowania. Przetwornik — **kodek** (ADC + DAC + wzmacniacze, filtry, mikser) — trzeba przy tym skonfigurować przez I²C lub SPI: zegary, format, zasilanie bloków analogowych, routing wejść i wyjść. FPGA pracuje albo jako master zegarów (generuje BCLK i WCLK), albo jako slave. Na rozmowie pytają o relacje zegarów (MCLK, BCLK, fs), o opóźnienie jednego bitu w I²S i o to, co trzeba zrobić, żeby kodek w ogóle wydał dźwięk.

## Intuicja

I²S to taśmociąg z próbkami: BCLK to rytm taśmy (jeden bit na takt), WCLK — chorągiewka „teraz lewy kanał / teraz prawy”, dane to bity próbek, najstarszy pierwszy. W I²S najstarszy bit pojawia się **jeden takt po zmianie chorągiewki** — taki zwyczaj z czasów, gdy odbiornik potrzebował chwili na przygotowanie. Kodek to mikser studyjny bez gałek: po włączeniu wszystkie suwaki są na zero, kanały wyłączone — dopiero lista instrukcji przez I²C ustawia, co gdzie płynie.

## Teoria

### Sygnały i zegary

| Sygnał | Nazwa w I²S | Znaczenie | Tu (DECA) |
|---|---|---|---|
| MCLK | — | zegar główny przetwornika (256·fs, 512·fs albo wejście PLL kodeka) | 12,5 MHz z PLL FPGA |
| BCLK | SCK | zegar bitów: fs × bity w ramce | 12,5 MHz / 4 = 3,125 MHz (64 bity na ramkę) |
| WCLK (LRCLK) | WS | 0 — kanał lewy, 1 — prawy; okres = 1/fs | BCLK / 64 = 48,828 kHz |
| DIN / DOUT | SD | dane: najstarszy bit pierwszy, w kodzie uzupełnień do dwóch | 24 bity w 32-bitowym slocie |

Format **I²S**: dane zmieniają się przy opadającym BCLK, odbiornik próbkuje przy narastającym; MSB pojawia się w pierwszym takcie BCLK **po** zmianie WCLK. **Left-justified** — MSB razem ze zmianą WCLK; **right-justified** — LSB na końcu slotu; **DSP/TDM** — krótki impuls ramki i wiele kanałów jeden po drugim. Słowo krótsze od slotu (24 bity w 32) jest wyrównane do lewej, reszta to zera — odbiornik o innej długości słowa i tak dostaje poprawną wartość (najwyższe bity są na swoich miejscach).

**Kto jest masterem?** Ten, kto generuje BCLK i WCLK. Tu FPGA (zegary w jednej domenie z logiką, prosta synchronizacja przetwarzania z ramką); kodek pracuje jako slave, a jego przetworniki taktuje MCLK. Wszystkie trzy zegary muszą być **zgodne**: kodek dzieli MCLK przez NDAC·MDAC·DOSR, co musi dać dokładnie fs = WCLK — tu 12,5 MHz / (1 · 2 · 128) = 48,828 kHz. Dla 48 kHz dokładnie potrzeba MCLK = 12,288 MHz (albo PLL w kodeku).

### Master I²S w FPGA

[i2s_master](hdl/verilog/i2s_master.v) liczy takty clk w ramce (0…255): pozycja bitu n = licznik / 4, faza = licznik mod 4. BCLK = bit 1 licznika, WCLK = bit 7, wszystkie wyjścia rejestrowane razem. Bit nadawany w takcie n to bit n − 1 ramki {L, 0×8, P, 0×8} (opóźnienie I²S); odbierany bit jest próbkowany w fazie 3 (po narastającym BCLK), z zapasem 160–240 ns na opóźnienie kodeka. Impuls `ramka` raz na 256 taktów: przyjęto próbki do wysłania, podano odebrane.

### Konfiguracja TLV320AIC3254

Rejestry są w **stronach** po 128: zapis do rejestru 0 wybiera stronę. Typowa sekwencja (na podstawie przykładów z karty katalogowej TI, dostosowana do zegarów DECA):

| Strona | Rejestry | Działanie |
|---|---|---|
| 0 | 0x01 = 0x01, potem przerwa ≥ 1 ms | programowy reset |
| 0 | 0x0B/0x0C = 0x81/0x82, 0x0D/0x0E = 0x00/0x80 | NDAC = 1, MDAC = 2, DOSR = 128 (fs = MCLK/256) |
| 0 | 0x12/0x13/0x14 = 0x81/0x82/0x80 | NADC = 1, MADC = 2, AOSR = 128 |
| 0 | 0x1B = 0x20 | I²S, słowo 24 bity, BCLK i WCLK wejściami (kodek slave) |
| 1 | 0x01 = 0x08, 0x02 = 0x00, 0x7B = 0x01 | zasilanie analogowe (zewnętrzne AVDD), czas ładowania referencji |
| 1 | 0x0C–0x0F = 0x08, 0x10–0x13 = 0x00, 0x09 = 0x3C | DAC → HPL/HPR i LOL/LOR, wzmocnienie 0 dB, włączenie wyjść |
| 1 | 0x34/0x36/0x37/0x39 = 0x40, 0x3B/0x3C = 0x0C | wejścia IN1 → MICPGA (10 kΩ), wzmocnienie 6 dB |
| 0 | 0x3F = 0xD6, 0x40 = 0x00, 0x51 = 0xC0, 0x52 = 0x00 | włączenie i odciszenie DAC i ADC |

Wartości routingu wejść i wyjść zależą od tego, do których końcówek kodeka są podłączone gniazda — przed zmianami trzeba sprawdzić schemat DECA i *Application Reference Guide*. [i2c_zapisy](hdl/verilog/i2c_zapisy.v) to uogólniony `adv7513_konfig` z [24.02](../24-wideo-i-grafika/24.02-hdmi-i-dvi-kodowanie-tmds-i-nadajnik-adv7513-na.md): tablica jest **parametrem** (N wpisów po 16 bitów), a wpis z rejestrem 0xFF to przerwa (n · 1024 ćwiartek okresu SCL) — tu 2,5 ms po programowym resecie. W [deca/audio](deca/audio) sekwencja startu to: reset FPGA → 1 ms AUDIO_RESET_n = 0 → 2 ms → konfiguracja I²C (AUDIO_SPI_SELECT = 0 wybiera I²C, adres 0x18).

## Kod: VHDL

[hdl/vhdl/i2s_master.vhd](hdl/vhdl/i2s_master.vhd) — zegary z licznika, nadawanie przy opadającym BCLK (faza 0), odbiór po narastającym (faza 3):

```vhdl
bclk <= cnt(1);
wclk <= cnt(7);
if cnt(1 downto 0) = "00" then                     -- opadające BCLK: następny bit
  if n = 0 then dout <= '0'; else dout <= wy(63 - (n - 1)); end if;
end if;
if cnt(1 downto 0) = "11" and n /= 0 then          -- po narastającym BCLK: próbka din
  we(63 - (n - 1)) <= din;
end if;
```

## Kod: Verilog

[hdl/verilog/i2c_zapisy.v](hdl/verilog/i2c_zapisy.v) — tablica jako parametr i wpis-przerwa:

```verilog
parameter integer N      = 2,
parameter [16*N-1:0] TAB = {16'h00_00, 16'h01_01}
...
function [15:0] tab(input [7:0] i);
    tab = TAB[16 * (N - 1 - i) +: 16];         // wpis 0 w najstarszych bitach
endfunction
...
if (wpis[15:8] == 8'hFF) begin                 // wpis-przerwa: bez transakcji
    pz   <= {wpis[7:0], 10'd0};                // n · 1024 ćwiartek okresu SCL
    faza <= 2'd0;
    stan <= S_PRZERWA;
end
```

## Kod: SystemVerilog

[hdl/sv/tb_kodek.sv](hdl/sv/tb_kodek.sv) — model kodeka z rejestrem strony (rejestr 0 wybiera stronę, osobne pamięci stron):

```systemverilog
default: begin
    n_zap = n_zap + 1;
    if (rej == 8'd0) strona = bajt;
    else if (strona == 8'd0) mem0[rej[6:0]] = bajt;

```

## Co powstaje po syntezie

Yosys (LUT4): `i2s_master` — **222 LUT4, 156 przerzutników** (licznik, rejestry ramki nadawanej i odbieranej po 64 bity, próbki wyjściowe 2 × 24 bity); `i2c_zapisy` z tablicą domyślną — **167 LUT4, 63 przerzutniki** (tablica 42 wpisów kodeka to dodatkowo ok. 100 LUT na multiplekser stałych). Całość sterowania kodekiem to kilkaset elementów logicznych — mniej niż jeden filtr z [25.02](25.02-przetwarzanie-dzwieku-w-czasie-rzeczywistym.md).

## Weryfikacja

`tb_i2s` (Icarus, Verilator, GHDL) z modelem kodeka jako slave I²S (odbiór według formatu: licznik od zmiany WCLK, bity 1–24 slotu; nadawanie po opadającym BCLK z opóźnieniem 10 ns): 200 ramek losowych próbek w obie strony, ciągi porównane z automatycznym wyrównaniem opóźnienia potoku — **0 błędów w obu kierunkach**, BCLK **3,125 MHz**, WCLK **48,828 kHz**, **64 takty BCLK na ramkę**.

`tb_kodek` z modelem TLV320AIC3254 (adres 0x18, strony rejestrów): **41 zapisów w 14,75 ms** (42 wpisy, jeden to przerwa), wszystkie z ACK, przerwa po programowym resecie **2,57 ms**, rejestry kluczowe na stronach 0 i 1 zgodne (w tym ten sam numer rejestru 0x3C na dwóch stronach), strona końcowa 0.

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| I²S: dane zmieniane przy opadającym BCLK, próbkowane przy narastającym; MSB 1 takt po zmianie WCLK | format I²S |
| WCLK = fs; BCLK = fs × bity ramki (64 → 3,072 MHz przy 48 kHz); MCLK = 256·fs albo 512·fs | zegary audio |
| fs kodeka = MCLK / (NDAC · MDAC · DOSR) — musi równać się WCLK | konfiguracja AIC3254 |
| Słowo krótsze niż slot — wyrównane do lewej, reszta zera | długość słowa |
| AIC3254: strony rejestrów (rejestr 0), reset programowy + ≥ 1 ms, zasilanie analogowe przed wyjściami | kodek na DECA |
| Kolejność startu: zegary → reset kodeka → konfiguracja → odciszenie | każdy kodek |

## Typowe pułapki

- **Zegary niezgodne** (fs z dzielników MCLK ≠ WCLK) — trzaski co kilka ramek albo cisza.
- **Format I²S vs left-justified** — dźwięk z przesterowaniem albo dwa razy cichszy (przesunięcie o bit).
- **Konfiguracja przed ustaleniem MCLK lub przed końcem resetu kodeka** — część zapisów ginie.
- **Pominięcie stron rejestrów** — zapis trafia do rejestru o tym samym numerze na innej stronie.
- **Wyjście nie zasilone albo wyciszone** (power-up i mute to osobne bity) — ADC działa, DAC milczy.
- **Próbki ze znakiem traktowane jak bez znaku** — przy przetwarzaniu (25.02) przesunięcie składowej stałej i zniekształcenia.

## Pytania rekrutacyjne

1. **Jakie zegary potrzebne są do pracy kodeka audio przez I²S i jak są ze sobą powiązane?**

<details>
<summary>Odpowiedź</summary>

WCLK (LRCLK) o częstotliwości próbkowania fs, BCLK = fs × liczba bitów w ramce (np. 64 · fs) i zwykle MCLK — zegar przetworników, wielokrotność fs (256 · fs, 512 · fs) albo wejście PLL kodeka. Wszystkie muszą pochodzić z jednego źródła albo być zsynchronizowane, a dzielniki wewnątrz kodeka muszą dawać z MCLK dokładnie fs. Inaczej przetwornik i interfejs „rozjeżdżają się” i co jakiś czas próbka jest gubiona albo powtarzana (trzask).
</details>

2. **Czym różni się format I²S od left-justified?**

<details>
<summary>Odpowiedź</summary>

W I²S najstarszy bit próbki pojawia się jeden takt BCLK po zmianie WCLK, a WCLK = 0 oznacza kanał lewy. W left-justified MSB pojawia się razem ze zmianą WCLK, a polaryzacja WCLK jest zwykle odwrotna (1 — lewy). Pomylenie formatów przesuwa dane o bit: próbka jest dwukrotnie mniejsza albo większa i z przekłamanym znakiem — dźwięk zniekształcony, ale słyszalny, co utrudnia diagnozę.
</details>

3. **FPGA ma być masterem I²S. Jak zrealizujesz BCLK, żeby nie mieć problemów z analizą czasową?**

<details>
<summary>Odpowiedź</summary>

BCLK nie jako zegar logiki, tylko jako sygnał danych: licznik w domenie szybszego zegara (tu 12,5 MHz) i rejestry wyjściowe dla BCLK, WCLK i danych ustawiane razem. Dane zmieniam w fazie odpowiadającej opadającemu BCLK, odbiór próbkuję w fazie po narastającym — w obu przypadkach z zapasem wielu nanosekund, więc wystarczą zwykłe ograniczenia (albo false path przy tak wolnym interfejsie). Logika przetwarzania pracuje w tej samej domenie i dostaje impuls „nowa ramka” zamiast zegara WCLK.
</details>

## Zadania

1. Dodaj do `i2s_master` tryb left-justified (parametr) i test z modelem w tym formacie. **Kryterium zaliczenia:** `tb_i2s` w obu formatach, 0 błędów; wydruk pokazujący MSB w takcie zmiany WCLK.

2. Generator tonu: sinus 1 kHz z tablicy (ROM ćwiartki okresu) na wyjście DECA, głośność z przełączników. **Kryterium zaliczenia:** symulacja z odczytem kilkuset próbek i porównaniem z sinusem (błąd ≤ 1 LSB 16-bitowy); na płytce — czysty ton w słuchawkach.

3. Przełącz kodek na pracę jako master (BCLK i WCLK z kodeka, z jego PLL z MCLK 12,5 MHz → fs = 48 kHz dokładnie) i zrób z FPGA slave I²S. **Kryterium zaliczenia:** zmieniona tablica konfiguracji (rejestry PLL i 0x1B), odbiornik/nadajnik slave z testbenchem, w którym zegary pochodzą z modelu kodeka.
