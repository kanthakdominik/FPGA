## Po co to jest

W większym projekcie te same typy (piksel, nagłówek pakietu, kody operacji) i stałe (szerokości magistral, mapa rejestrów) są używane w dziesiątkach modułów. Pakiet trzyma je w jednym miejscu. Parametry **typu** pozwalają napisać blok uniwersalny — kolejkę, linię opóźniającą, multiplekser — raz, i używać go dla dowolnych danych: bajtów, pikseli, całych struktur. To SystemVerilogowy odpowiednik szablonów z C++.

## Intuicja

Pakiet to wspólny słownik projektu: każdy moduł, który go zaimportuje, rozumie te same słowa (`rgb_t`, `GRAY_LUMA`). Parametr typu to „pudełko o nieokreślonym kształcie”: linia opóźniająca przesuwa pudełka z etapu na etap i nie musi wiedzieć, co jest w środku — wystarczy, że wie, ile bitów zajmują.

## Teoria

### Pakiet

```systemverilog
package img_pkg;
    typedef struct packed { logic [7:0] r, g, b; } rgb_t;
    typedef enum logic [1:0] {GRAY_AVG, GRAY_LUMA, GRAY_RED} gray_mode_t;
    localparam int PIX_W = $bits(rgb_t);
    function automatic logic [7:0] luma(rgb_t p); … endfunction
endpackage
```

Zawartość: `typedef`, `localparam`/`parameter` (stałe), funkcje i zadania (`automatic`), klasy (weryfikacja). Pakiet **nie** może zawierać modułów, sygnałów sterowanych przez `assign` ani instancji.

Sposoby użycia:

| Zapis | Znaczenie |
|-------|-----------|
| `img_pkg::rgb_t` | odwołanie z nazwą pakietu — najbezpieczniejsze |
| `import img_pkg::rgb_t;` | import jednej nazwy |
| `import img_pkg::*;` | import wszystkich nazw (używanych w kodzie) |
| `module m import img_pkg::*; #(…) (…);` | import w nagłówku — nazwy dostępne także w deklaracjach portów |

Zasady:

- **Nie importuj w przestrzeni `$unit`** (poza modułem, na początku pliku) — import dotyczy wtedy kolejnych plików w tej samej kompilacji, zależnie od kolejności plików i narzędzia.
- Pakiet musi być skompilowany **przed** modułami, które go używają — skrypt testów tej bazy ustawia `*_pkg.sv` na początku listy plików ([06.07](06.07-co-z-systemveriloga-obsluguja-narzedzia-syntezy.md)).
- Dwa pakiety z tą samą nazwą typu i `import *` z obu — konflikt; rozwiąż przez odwołanie z prefiksem.

### Parametry typu

```systemverilog
module type_delay #(
    parameter type T     = logic [7:0],    // domyślny typ
    parameter int  DEPTH = 2
) (
    input  logic clk,
    input  T     d,
    output T     q
);
    T stage [DEPTH];
    …
```

Instancja: `type_delay #(.T(img_pkg::rgb_t), .DEPTH(2)) u_rgb (…);`. Wewnątrz modułu typ `T` jest „nieprzezroczysty” — można go przypisywać, przechowywać i porównywać; `$bits(T)` podaje jego szerokość. Jeśli moduł musi znać pola, typ powinien przyjść z pakietu, a nie z parametru.

### Odpowiedniki

| SystemVerilog | VHDL-2008 | Verilog |
|---------------|-----------|---------|
| `package … endpackage` | `package` / `package body` | brak — `` `include `` |
| `parameter type T` | `generic (type T)` | brak — parametr szerokości, dane spłaszczone |
| `import pkg::*` | `use work.pkg.all` | — |
| funkcja w pakiecie | funkcja w pakiecie, z parametrami bez ograniczeń ([04.07](../04-vhdl/04.07-pakiety-funkcje-procedury-i-atrybuty.md)) | funkcja w module |

Obsługa w syntezie: parametry typu w SystemVerilogu przyjmują Quartus Prime Pro, Vivado i nowsze narzędzia; Quartus Prime Lite/Standard obsługuje je tylko częściowo. Generic typów VHDL-2008: GHDL, Questa, Vivado (z ograniczeniami); Quartus Lite — nie. Szczegóły — [06.07](06.07-co-z-systemveriloga-obsluguja-narzedzia-syntezy.md).

- `generic (type T; DEPTH : positive)` — testbench podstawia rekord `rgb_t` i podtyp `std_logic_vector(7 downto 0)`. GHDL to obsługuje; Quartus Lite nie, więc w projekcie na DECA trzeba by użyć wersji z wektorem.

## Co powstaje po syntezie

`DEPTH · $bits(T)` przerzutników i żadnej logiki — dla `rgb_t` i DEPTH = 2 to 48 rejestrów. Wynik Yosysa dla wersji Verilog (W = 8, DEPTH = 2): 16 przerzutników, 0 LUT — w logu CI.

## Weryfikacja

Testbench zapisuje każdą podaną wartość w historii (kolejka w SV, tablica w Verilogu i VHDL) i sprawdza, czy po `DEPTH` taktach pojawia się na wyjściu. Pierwsza wersja testbencha miała błąd w modelu instancji 8-bitowej (porównywała z wartością sprzed dwóch taktów zamiast jednego) — wykrył go CI we wszystkich trzech językach. Gdy test zawodzi tak samo w trzech niezależnych implementacjach układu, błąd jest raczej w teście niż w układzie.

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| Typy i stałe wspólne dla modułów — w pakiecie | organizacja kodu |
| Import w module (lub nagłówku modułu), nie w `$unit` | SystemVerilog |
| Pakiet kompilowany przed użytkownikami | kolejność plików |
| `parameter type T` + `$bits(T)` — bloki niezależne od typu danych | biblioteki bloków |
| Parametry typu nie wszędzie przechodzą syntezę — sprawdź narzędzie | Quartus Lite, starsze narzędzia |

## Typowe pułapki

- **`import pkg::*` na początku pliku poza modułem** — działa w jednym narzędziu, w innym zależy od kolejności plików.
- **Ta sama nazwa w dwóch pakietach** — przy imporcie `*` z obu niejednoznaczność; prefiks `pkg::`.
- **Zmiana pakietu wymusza rekompilację wszystkiego** — duże pakiety „na wszystko” spowalniają pracę; dziel tematycznie.
- **Moduł z parametrem typu używający pól** (`d.r`) — działa tylko dla struktur z polem `r`; to nie jest już blok uniwersalny.

## Pytania rekrutacyjne

1. **Jak współdzielić typy i stałe między modułami w SystemVerilogu?**

<details>
<summary>Odpowiedź</summary>

Przez pakiet (`package … endpackage`) z `typedef`, `localparam` i funkcjami `automatic`. Moduły importują go (`import pkg::*;` w module albo w nagłówku modułu) lub odwołują się z prefiksem `pkg::nazwa`. Pakiet kompiluje się przed modułami. Nie importuje się w przestrzeni `$unit`, bo wynik zależy od kolejności kompilacji.
</details>

2. **Do czego służy `parameter type`?**

<details>
<summary>Odpowiedź</summary>

Do pisania bloków niezależnych od typu danych — kolejek, linii opóźniających, rejestrów potokowych, multiplekserów — które działają tak samo dla bajtu, piksela czy całej struktury nagłówka. Szerokość typu odczytuje się `$bits(T)`. To odpowiednik `generic (type T)` w VHDL-2008 i szablonów w C++.
</details>
