## Po co to jest

SystemVerilog to ogromny standard (IEEE 1800 ma ponad 1300 stron), a każde narzędzie obsługuje inny jego podzbiór. Kod, który przechodzi w Verilatorze, może zostać odrzucony przez Quartusa Lite; kod syntezowany w Vivado — przez Yosysa. Projektant musi wiedzieć, których konstrukcji może bezpiecznie używać w danym łańcuchu narzędzi, zanim napisze tysiące linii. Ten temat daje mapę i — co ważniejsze — metodę sprawdzania.

## Intuicja

SystemVerilog przypomina język, którym mówi kilka regionów: rdzeń rozumieją wszyscy, ale idiomy lokalne — tylko część. Bezpiecznie jest pisać w rdzeniu, a przed użyciem idiomu sprawdzić, czy zrozumie go każdy, z kim trzeba się porozumieć: symulator, syntezator, linter, narzędzie formalne.

## Teoria

### Podział standardu

| Część | Przykłady | Synteza |
|-------|-----------|---------|
| RTL — rdzeń | `logic`, `always_comb`/`always_ff`, `enum`, `struct packed`, `typedef`, pakiety, `unique`/`priority` | tak (w różnym zakresie) |
| RTL — rozszerzenia | interfejsy i modporty, parametry typu, `case inside`, operatory strumieniowe, tablice spakowane wielowymiarowe na portach | zależnie od narzędzia |
| asercje | `assert` natychmiastowe, SVA (`property`, `sequence`) | pomijane; SVA — weryfikacja formalna |
| weryfikacja | klasy, losowanie z ograniczeniami (`rand`, `constraint`), pokrycie (`covergroup`), kolejki, tablice asocjacyjne | nie |

### Mapa obsługi (stan wg dokumentacji narzędzi)

| Konstrukcja | Quartus Prime Lite/Standard | Quartus Prime Pro | Vivado | Yosys (wbudowany parser) | Yosys + yosys-slang | Verilator (symulacja) |
|-------------|-----------------------------|-------------------|--------|--------------------------|---------------------|-----------------------|
| `logic`, `always_ff/comb/latch` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `enum`, `typedef` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `struct packed` | ✓ | ✓ | ✓ | ✓ (nowsze wersje) | ✓ | ✓ |
| `union packed` | ✓ | ✓ | ✓ | częściowo | ✓ | ✓ |
| pakiety, `import` | ✓ | ✓ | ✓ | częściowo | ✓ | ✓ |
| `unique` / `priority` | ✓ | ✓ | ✓ | ✓ (traktowane jako `case`) | ✓ | ✓ (sprawdzanie z `--assert`) |
| interfejsy i modporty | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ |
| `parameter type` | do sprawdzenia | ✓ | ✓ | ✗ | ✓ | ✓ |
| `case inside`, `inside` | do sprawdzenia | ✓ | ✓ | częściowo | ✓ | ✓ |
| `$countones`, `$onehot`, strumieniowe `{<<{}}` | do sprawdzenia | ✓ | ✓ | częściowo | ✓ | ✓ |
| asercje natychmiastowe | pomijane | pomijane | pomijane | pomijane (lub formalnie) | j.w. | ✓ |

Legenda: ✓ — obsługiwane według dokumentacji producenta lub testów sv-tests; „do sprawdzenia” — dokumentacja nie daje jednoznacznej odpowiedzi albo obsługa zależy od wersji. Tabela opisuje stan w czasie pisania; **przed użyciem konstrukcji w projekcie sprawdź ją w konkretnej wersji narzędzia** (zadanie 1).

Wnioski praktyczne dla tej bazy:

- Kod SV w `hdl/sv/` jest symulowany w Verilatorze i używa konstrukcji z rdzenia oraz interfejsów — powinien przejść przez Quartusa Lite; wyjątki to `parameter type` ([06.03](06.03-pakiety-i-parametryzacja-typami.md)) i części `inside`/funkcji systemowych, które trzeba sprawdzić.
- Moduły nadrzędne projektów DECA (`deca_top.sv`) używają tylko rdzenia — z założenia przechodzą przez każdy syntezator.
- CI syntezuje w Yosysie wersje Verilog, bo wbudowany parser SV Yosysa nie obsługuje m.in. interfejsów.

### Jak sprawdzić obsługę konstrukcji

1. **Mały przypadek testowy** — moduł z jedną konstrukcją jako modułem nadrzędnym, kompilacja do końca syntezy (`quartus_map`, `synth_design`, `yosys -p synth`).
2. **Raport** — czy narzędzie zgłosiło błąd, ostrzeżenie o ignorowaniu konstrukcji, czy zbudowało oczekiwaną logikę (*RTL Viewer*, `stat`).
3. **Symulacja po syntezie** — dla konstrukcji, które mogą zostać zinterpretowane inaczej (`unique`, `priority`): netlista po syntezie w tym samym testbenchu.
4. **Zapis w repozytorium** — tabela „co działa w naszym łańcuchu narzędzi” oszczędza zespołowi powtarzania prób.

### Projekty mieszane

Wszystkie trzy narzędzia producentów (Quartus, Vivado, Questa) pozwalają mieszać VHDL, Verilog i SystemVerilog w jednym projekcie: moduł VHDL może instancjonować moduł SV i odwrotnie. Granica musi przejść przez porty prostych typów: `std_logic`/`std_logic_vector` ↔ `logic`/`logic [N-1:0]`; struktury, interfejsy, typy wyliczeniowe i rekordy na granicy języków zwykle nie są obsługiwane. Dlatego moduły tej bazy mają porty z wektorami, a typy użytkownika — wewnątrz.

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| Rdzeń RTL (`logic`, `always_*`, `enum`, `struct packed`, pakiety) — bezpieczny we wszystkich narzędziach FPGA | SystemVerilog |
| Interfejsy, `parameter type`, `inside` — sprawdź w swoim narzędziu i wersji | SystemVerilog |
| Klasy, losowanie, pokrycie — tylko weryfikacja | SystemVerilog |
| Na granicy języków — porty z wektorami, bez typów użytkownika | projekty mieszane |
| Wątpliwość = mały przypadek testowy + raport syntezy | każda nowa konstrukcja |

## Typowe pułapki

- **„Działa w Verilatorze, więc się zsyntezuje”** — Verilator to symulator; jego obsługa SV nie mówi nic o syntezatorze.
- **Konstrukcja zignorowana z ostrzeżeniem** — niektóre narzędzia pomijają nieobsługiwane elementy (np. asercje, ale czasem też część logiki) i kończą syntezę sukcesem. Czytaj ostrzeżenia ([03.04](../03-przeplyw-projektowy/03.04-raporty-zasoby-czasy-i-ostrzezenia-ktorych-nie.md)).
- **Różne domyślne wersje języka** — Quartus Lite trzeba przełączyć na SystemVerilog-2005 (`VERILOG_INPUT_VERSION SYSTEMVERILOG_2005` albo pliki `.sv`); skrypt `deca_projekt.tcl` dodaje pliki `.sv` jako `SYSTEMVERILOG_FILE`.

## Pytania rekrutacyjne

1. **Których konstrukcji SystemVeriloga używasz w kodzie syntezowalnym?**

<details>
<summary>Odpowiedź</summary>

`logic`, `always_ff`/`always_comb`, `typedef enum` z typem bazowym, `struct packed`, pakiety z typami i funkcjami `automatic`, `unique`/`priority case` z czytaniem ostrzeżeń, `case inside`, interfejsy z modportami do magistral, parametry typu w blokach bibliotecznych — o ile obsługuje je łańcuch narzędzi projektu. Nie używam klas, losowania ani pokrycia w RTL. Przed użyciem mniej typowej konstrukcji sprawdzam ją małym przypadkiem testowym w syntezatorze docelowym.
</details>

2. **Jak połączyć moduł VHDL z modułem SystemVerilog w jednym projekcie?**

<details>
<summary>Odpowiedź</summary>

Narzędzia producentów kompilują oba języki do wspólnej biblioteki i pozwalają na instancję w obie strony — w VHDL przez deklarację komponentu (albo `entity work.nazwa` w niektórych narzędziach), w SV zwykłą instancją modułu. Porty na granicy muszą być prostych typów: bity i wektory. Struktury, rekordy, interfejsy i typy wyliczeniowe trzeba rozpakować na wektory w cienkiej warstwie opakowania.
</details>

## Zadania

1. Utwórz w Quartusie Prime Lite projekt dla DECA z każdym modułem z `hdl/sv/` tego modułu jako modułem nadrzędnym (w razie potrzeby z opakowaniem ustalającym parametry) i uruchom samą syntezę (`quartus_map`). **Kryterium zaliczenia:** tabela z wynikiem dla każdego modułu (przeszedł / błąd z treścią komunikatu) i uzupełnione wiersze „do sprawdzenia” w tabeli tej lekcji dla Twojej wersji Quartusa.

2. Zainstaluj Yosysa z wtyczką *yosys-slang* (np. w OSS CAD Suite) i zsyntezuj `skid_buffer.sv` razem z `stream_if.sv`. Porównaj liczbę komórek z wynikiem dla `skid_buffer.v` w CI. **Kryterium zaliczenia:** obie wersje dają tę samą liczbę przerzutników (18).
