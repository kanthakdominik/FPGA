## Po co to jest

VHDL jest językiem **silnie typowanym**: nie da się dodać `std_logic_vector` do `integer`, ani przypisać `unsigned` do `signed` bez jawnej konwersji. Początkujących to irytuje, zawodowców chroni — błąd, który w Verilogu cicho zamienia liczbę ujemną na ogromną dodatnią ([01.01](../01-logika-cyfrowa/01.01-systemy-liczbowe-kody-i-liczby-ze-znakiem.md)), w VHDL nie przejdzie kompilacji. Trzeba tylko znać typy i drogi konwersji między nimi.

## Intuicja

`std_logic_vector` to **rząd przewodów** — sam w sobie nie jest liczbą. `unsigned` i `signed` to ten sam rząd przewodów z **naklejką**, jak go czytać: bez znaku albo w U2. Zmiana naklejki (`unsigned(v)`, `signed(v)`) nic nie kosztuje w sprzęcie. `integer` to liczba „matematyczna” — wygodna do liczników i indeksów, ale bez dostępu do pojedynczych bitów.

## Teoria

### Typy, których się używa

| Typ | Pakiet | Wartości | Zastosowanie |
|-----|--------|----------|--------------|
| `std_logic` | `std_logic_1164` | 9 wartości: `'U' 'X' '0' '1' 'Z' 'W' 'L' 'H' '-'` | pojedyncze sygnały |
| `std_logic_vector` | `std_logic_1164` | tablica `std_logic` | porty, magistrale, dane bez interpretacji |
| `unsigned`, `signed` | `numeric_std` | tablica `std_logic` interpretowana jako liczba | arytmetyka |
| `integer`, `natural`, `positive` | `std` | liczby całkowite (co najmniej 32-bitowe) | liczniki, indeksy, generic |
| `boolean` | `std` | `false`, `true` | warunki, generic |
| typ wyliczeniowy | własny | np. `(IDLE, RUN, DONE)` | stany automatu |
| rekord | własny | grupa pól różnych typów | magistrale, interfejsy |
| tablica | własna | np. `array (0 to 15) of unsigned(7 downto 0)` | pamięci, banki rejestrów |

Wartości `std_logic` ważne w praktyce: `'0'`, `'1'`, `'Z'` (wysoka impedancja — bufory trójstanowe), `'U'` (niezainicjalizowany — widoczny w symulacji przed resetem), `'X'` (konflikt dwóch sterowników), `'-'` (wartość obojętna). `std_logic` jest typem **rozstrzyganym** (*resolved*): gdy sygnał ma kilka sterowników, funkcja rozstrzygająca wylicza wynik (np. `'0'` i `'1'` → `'X'`) — [04.09](04.09-pulapki-vhdl-rozdzielczosc-sygnalow-konwersje-i.md).

### Konwersje

```text
                 unsigned(v) / signed(v)                to_integer(x)
std_logic_vector ───────────────────────► unsigned/signed ─────────────► integer
                 ◄─────────────────────── ◄─────────────
                 std_logic_vector(x)       to_unsigned(i, N) / to_signed(i, N)
```

| Z → do | Zapis | Koszt w sprzęcie |
|--------|-------|------------------|
| `std_logic_vector` → `unsigned` / `signed` | `unsigned(v)` — **zmiana typu** (*type conversion*) | zero |
| `unsigned` / `signed` → `std_logic_vector` | `std_logic_vector(x)` | zero |
| `unsigned` ↔ `signed` | `signed(u)`, `unsigned(s)` — ta sama liczba bitów, inna interpretacja | zero |
| `unsigned` / `signed` → `integer` | `to_integer(x)` | zero (dla syntezy) |
| `integer` → `unsigned` / `signed` | `to_unsigned(i, N)`, `to_signed(i, N)` — trzeba podać szerokość | zero |
| zmiana szerokości | `resize(x, N)` — dla `signed` powiela bit znaku, dla `unsigned` dopisuje zera | zero (połączenia) |

Zasada: **porty jako `std_logic_vector`, arytmetyka w środku na `unsigned`/`signed`**. Konwersja jest wtedy w jednym, widocznym miejscu.

### Arytmetyka `numeric_std` i szerokości

- `a + b` ma szerokość **dłuższego** argumentu — przeniesienie ginie, jeśli się o nie nie zadba (`resize`, [01.04](../01-logika-cyfrowa/01.04-uklady-arytmetyczne-sumatory-przeniesienia.md)).
- `a * b` ma szerokość **sumy** szerokości argumentów.
- `unsigned + natural` i `signed + integer` są zdefiniowane (stała zostaje dopasowana do szerokości wektora).
- Porównania `<`, `=` działają na wartościach liczbowych (inaczej niż porównanie `std_logic_vector` różnej długości — [04.09](04.09-pulapki-vhdl-rozdzielczosc-sygnalow-konwersje-i.md)).
- `shift_left`, `shift_right` — dla `signed` przesunięcie w prawo jest arytmetyczne.

### Typy wyliczeniowe, rekordy, tablice

```vhdl
type state_t is (IDLE, LOAD, RUN, DONE);           -- kodowanie wybiera syntezator
signal state : state_t := IDLE;

type bus_t is record                               -- grupa sygnałów jako jeden obiekt
  addr  : unsigned(7 downto 0);
  data  : std_logic_vector(31 downto 0);
  valid : std_logic;
end record;
signal req : bus_t;
-- req.addr <= x"10"; req.valid <= '1';

type mem_t is array (0 to 255) of std_logic_vector(7 downto 0);  -- pamięć
```

### Agregaty

```vhdl
x <= (others => '0');                    -- wszystkie bity
x <= (7 => '1', others => '0');          -- wybrane bity, stały indeks
x <= '0' & (W - 2 downto 0 => '1');      -- 011…1 przy indeksie zależnym od generic
```

Agregat z **niestatycznym** wyborem (zależnym od generic, np. `W - 1 => '0'`) **nie może** stać obok `others`. Dokładnie ten błąd zgłosił GHDL dla pierwszej wersji `sat_add` w CI tej bazy — dlatego stałe są zbudowane konkatenacją.

### Odpowiedniki w Verilogu i SystemVerilogu

| VHDL | Verilog | SystemVerilog |
|------|---------|---------------|
| `std_logic` (9 wartości) | `wire`/`reg` (4 wartości: 0, 1, x, z) | `logic` (4 wartości) |
| `std_logic_vector` | `wire [N-1:0]` | `logic [N-1:0]` |
| `unsigned` / `signed` | wektor / wektor `signed` | jak Verilog |
| `integer` | `integer` (32 bity) | `int` (2 wartości, 32 bity) |
| typ wyliczeniowy | `localparam` | `typedef enum` |
| rekord | brak | `typedef struct packed` |
| konwersje jawne, kontrola typów | niejawne, bez kontroli | rzutowania `signed'()`, `W'()`, ostrzeżenia narzędzi |

## Kod: VHDL

<!-- plik: hdl/vhdl/sat_add.vhd -->
Pliki: [sat_add.vhd](hdl/vhdl/sat_add.vhd) · testbench: [tb_sat_add.vhd](hdl/vhdl/tb_sat_add.vhd)

- Porty są `std_logic_vector`, a obliczenia — na `signed`: `resize(signed(a), W + 1)` zmienia interpretację i poszerza słowo z powieleniem bitu znaku.
- Przepełnienie: bity `sum(W)` i `sum(W - 1)` różne — wynik nie mieści się w W bitach ([01.04](../01-logika-cyfrowa/01.04-uklady-arytmetyczne-sumatory-przeniesienia.md)). Wtedy wyjście dostaje stałą `MAX_VAL` albo `MIN_VAL`, zależnie od znaku prawdziwej sumy.
- Nasycanie (*saturation*) to standard w przetwarzaniu sygnałów: przepełniony sygnał audio z zawinięciem daje głośny trzask, z nasyceniem — tylko obcięcie szczytu.

## Kod: Verilog

<!-- plik: hdl/verilog/sat_add.v -->
Pliki: [sat_add.v](hdl/verilog/sat_add.v) · testbench: [tb_sat_add.v](hdl/verilog/tb_sat_add.v)

- Porty zadeklarowane jako `signed`. Gdy **wszystkie** argumenty wyrażenia są `signed`, poszerzenie do szerokości `sum` powiela bit znaku. Jeden argument bez znaku i całe wyrażenie liczy się bez znaku — VHDL na to nie pozwoli, Verilog tak.

## Kod: SystemVerilog

<!-- plik: hdl/sv/sat_add.sv -->
Pliki: [sat_add.sv](hdl/sv/sat_add.sv) · testbench: [tb_sat_add.sv](hdl/sv/tb_sat_add.sv)

- Stałe jako `localparam logic signed [W-1:0]`, logika w `always_comb`. Testbench porównuje `int'(y)` z liczbą całkowitą — rzutowanie `int'` na sygnale `signed` zachowuje znak.

## Co powstaje po syntezie

Yosys (CI, W = 8): **32 LUT4**, bez przerzutników — sumator 9-bitowy, wykrycie przepełnienia i multiplekser 8-bitowy z trzech źródeł. W MAX 10 sumator idzie na łańcuch przeniesień (ok. 9 LE), multiplekser — ok. 8–16 LE.

## Weryfikacja

`tb_sat_add` sprawdza wszystkie $16 \times 16 = 256$ par liczb 4-bitowych ze znakiem (−8…7). Model: suma liczb całkowitych obcięta do przedziału −8…7; `sat` musi być 1 dokładnie wtedy, gdy obcięcie nastąpiło. Pętla po `integer` i konwersja `to_signed(i, W)` w testbenchu to wygodny wzorzec testów wyczerpujących.

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| Porty `std_logic_vector`, arytmetyka na `unsigned`/`signed` | styl kodu VHDL |
| `unsigned(v)`, `signed(v)`, `std_logic_vector(x)` — zmiana typu bez kosztu | konwersje |
| `to_integer(x)`, `to_unsigned(i, N)`, `to_signed(i, N)` | liczba ↔ wektor |
| `resize`: `signed` powiela bit znaku, `unsigned` dopisuje zera | zmiana szerokości |
| `a + b` ma szerokość dłuższego argumentu, `a * b` — sumę szerokości | `numeric_std` |
| Agregat z wyborem zależnym od generic nie może stać obok `others` | stałe parametryzowane |

## Typowe pułapki

- ⚠️ **Arytmetyka na `std_logic_vector`.** Bez niestandardowych pakietów się nie skompiluje — i dobrze. Najpierw `unsigned(…)`/`signed(…)`.
- **`to_integer` na wektorze szerszym niż 31 bitów.** `integer` w większości narzędzi ma 32 bity ze znakiem; wektor 32-bitowy bez znaku nie zmieści się w zakresie.
- **Nieograniczony `integer` jako sygnał.** `signal cnt : integer;` to 32 bity w syntezie. Zawsze podawaj zakres: `natural range 0 to 999`.
- **`signed(u)` zamiast `signed(resize(u, N + 1))`.** Liczba bez znaku z ustawionym najstarszym bitem po zmianie typu staje się ujemna ([04.09](04.09-pulapki-vhdl-rozdzielczosc-sygnalow-konwersje-i.md)).

## Pytania rekrutacyjne

1. **Jaka jest różnica między `std_logic` a `std_ulogic`?**

<details>
<summary>Odpowiedź</summary>

Oba mają te same 9 wartości. `std_ulogic` jest nierozstrzygany — sygnał tego typu może mieć tylko jeden sterownik, a drugi to błąd kompilacji. `std_logic` jest podtypem rozstrzyganym: wiele sterowników jest dozwolonych, a wynik wylicza funkcja rozstrzygająca (np. `'0'` i `'1'` daje `'X'`). W kodzie syntezowalnym `std_ulogic` wykrywa przypadkowe wielokrotne sterowanie już przy kompilacji.
</details>

2. **Jak dodać dwie liczby `std_logic_vector` ze znakiem z zachowaniem przeniesienia?**

<details>
<summary>Odpowiedź</summary>

`sum <= resize(signed(a), N + 1) + resize(signed(b), N + 1);` — zmiana typu na `signed`, poszerzenie z powieleniem bitu znaku, dodawanie na N + 1 bitach. Wynik z powrotem: `std_logic_vector(sum)`.
</details>

3. **Ile bitów zajmie `signal x : integer range 0 to 1000;`?**

<details>
<summary>Odpowiedź</summary>

10 bitów, bo $2^{10} = 1024 > 1000$. Syntezator wyznacza szerokość z zakresu. Bez zakresu `integer` miałby 32 bity.
</details>

## Zadania

1. Zapisz w VHDL konwersję: 12-bitowa próbka bez znaku z przetwornika ADC (`std_logic_vector`) na 13-bitową liczbę ze znakiem po odjęciu połowy zakresu (2048). **Kryterium zaliczenia:** dla 0 wynik −2048, dla 4095 wynik +2047.

<details>
<summary>Odpowiedź</summary>

```vhdl
y <= signed(resize(unsigned(adc), 13)) - 2048;
```

Najpierw `unsigned`, poszerzenie zerem do 13 bitów (wartość dodatnia), zmiana typu na `signed` (bit znaku = 0), potem odejmowanie stałej.
</details>

2. Zdefiniuj rekord `pixel_t` z polami `r`, `g`, `b` (po 8 bitów `unsigned`) i funkcję zwracającą jasność $(r + 2g + b) / 4$. **Kryterium zaliczenia:** testbench sprawdza wynik dla bieli (255), czerni (0) i czystej zieleni (127).
