## Po co to jest

Karta microSD to najtańszy sposób na gigabajty nieulotnej pamięci wymiennej: rejestratory danych, odtwarzanie obrazów i dźwięku, ładowanie programu procesora, logi z urządzenia w terenie. Najprościej obsłużyć ją w **trybie SPI** — cztery linie, kontroler na kilkuset elementach logicznych. Tryb natywny SD (4 linie danych, do 50–104 MB/s) wymaga więcej logiki albo IP. Na rozmowie pytają o sekwencję inicjalizacji (CMD0, CMD8, ACMD41), o różnicę SDSC/SDHC w adresowaniu, o CRC i o to, dlaczego karta „czasem” się nie inicjalizuje.

## Intuicja

Karta SD to urzędnik, który po przebudzeniu mówi tylko powoli i tylko w swoim języku. Najpierw trzeba poczekać, aż się obudzi (≥ 74 takty), potem przedstawić się w trybie „SPI, proszę” (CMD0 z CS = 0), zapytać, czy zna nowe zasady (CMD8), i powtarzać „zacznij pracę” (ACMD41), aż powie „gotowe”. Dopiero wtedy można mówić szybko i prosić o całe teczki po 512 stron.

## Teoria

### Tryb SPI: sygnały i rozkazy

Linie: SCLK, MOSI (= CMD), MISO (= DAT0), CS (= DAT3); tryb SPI 0, MSB pierwszy. Rozkaz to 48 bitów: `01` + numer (6 b) + argument (32 b) + CRC7 (7 b) + `1`. Karta odpowiada po 1–8 bajtach 0xFF (NCR). W trybie SPI CRC jest sprawdzane domyślnie tylko dla CMD0 i CMD8, ale liczenie go dla wszystkich rozkazów nic nie kosztuje (tutaj: funkcja `crc7`, wielomian x⁷ + x³ + 1).

| Rozkaz | Argument | Odpowiedź | Znaczenie |
|---|---|---|---|
| CMD0 GO_IDLE_STATE | 0 | R1 = 0x01 | reset; z CS = 0 → tryb SPI |
| CMD8 SEND_IF_COND | 0x1AA | R7: R1 + 4 B (echo 0x1AA) | karta v2.0+; uzgodnienie napięcia |
| CMD55 + ACMD41 | HCS = bit 30 | R1 = 0x01 (trwa), 0x00 (gotowa) | rozpoczęcie inicjalizacji; powtarzać do 0x00 (do ~1 s) |
| CMD58 READ_OCR | 0 | R3: R1 + OCR | bit 31 — koniec rozruchu, bit 30 **CCS**: 1 = SDHC/SDXC |
| CMD16 SET_BLOCKLEN | 512 | R1 | tylko SDSC (SDHC ma zawsze 512) |
| CMD17 READ_SINGLE_BLOCK | adres | R1, potem token 0xFE + 512 B + CRC16 | odczyt bloku |
| CMD24 WRITE_BLOCK | adres | R1; host: 0xFE + 512 B + CRC16; karta: odpowiedź danych + zajętość (MISO = 0) | zapis bloku |

**Adresowanie**: SDHC/SDXC (CCS = 1) — argument to **numer bloku 512 B**; SDSC — **adres w bajtach** (blok × 512). Pomylenie tego to klasyczny błąd: na karcie SDSC odczyt „bloku 5” czyta bajt 5.

### Inicjalizacja

1. Zasilanie, SCLK **100–400 kHz**, CS = 1, MOSI = 1, **≥ 74 takty** zegara.
2. CMD0 z CS = 0 → R1 = 0x01 (stan bezczynności, tryb SPI).
3. CMD8 0x1AA → R1 = 0x01 i echo 0x1AA: karta v2 (brak odpowiedzi/błąd — karta v1 albo MMC; ten kontroler ich nie obsługuje).
4. CMD55 + ACMD41 (HCS = 1) — powtarzać, aż R1 = 0x00 (karta kończy wewnętrzną inicjalizację, typowo 10–500 ms).
5. CMD58 → OCR: CCS określa adresowanie; dla SDSC CMD16 512.
6. Zegar w górę: do 25 MHz (*default speed*).

### Odczyt i zapis bloku

Po CMD17 karta wysyła 0xFF, dopóki dane nie są gotowe (do ~100 ms), potem **token 0xFE**, 512 bajtów i **CRC16** (CCITT, x¹⁶ + x¹² + x⁵ + 1). Błąd zamiast danych sygnalizuje token błędu (0000xxxx). Zapis (CMD24): host wysyła token 0xFE, dane i CRC16, karta odpowiada `xxx0_0101` (przyjęte) i trzyma MISO = 0 w czasie programowania (do ~250 ms). Dla wielu bloków — CMD18/CMD25 (odczyt/zapis ciągły) są znacznie szybsze niż pojedyncze bloki.

### Tryb SD (natywny)

Linia CMD (dwukierunkowa, rozkazy i odpowiedzi z CRC7) i 4 linie DAT, każda z własnym CRC16. Zegar do 25 MHz (*default speed*, 12,5 MB/s) albo 50 MHz (*high speed*, 25 MB/s), w UHS-I do 208 MHz przy 1,8 V. Inicjalizacja podobna (CMD0, CMD8, ACMD41, potem CMD2/CMD3 — identyfikacja i adres względny RCA, CMD7 — wybór karty, ACMD6 — szerokość szyny 4 bity). Kontroler natywny to większy automat i bufory, ale daje 4–8 razy wyższą przepustowość niż SPI.

### System plików

Bloki to surowa pamięć. Blok 0 to zwykle **MBR** (tablica partycji, sygnatura **0x55 0xAA** w bajtach 510–511) albo sektor rozruchowy FAT. Do czytania plików potrzeba sterownika FAT (FatFs i podobne) — zwykle na procesorze miękkim; czysta logika często zapisuje dane surowo do kolejnych bloków albo do wcześniej utworzonego, ciągłego pliku.

### Kontroler w tym temacie

[sd_spi](hdl/verilog/sd_spi.v): silnik bajtowy SPI 0 (dzielnik wolny 63 → 397 kHz przy 50 MHz, szybki 2 → 12,5 MHz), automat inicjalizacji z kodami błędów (1 — brak odpowiedzi, 2 — CMD0, 3 — CMD8, 4 — CMD55, 5 — ACMD41, 6 — CMD58/CMD16, 7 — R1 rozkazu CMD17, 8 — brak tokenu), odczyt bloku ze strumieniem bajtów (`dane`/`dane_wazne`/`koniec`) i weryfikacją CRC16 (`crc_ok`).

## Kod: VHDL

[hdl/vhdl/sd_spi.vhd](hdl/vhdl/sd_spi.vhd) — decyzje po odpowiedzi na kolejne rozkazy inicjalizacji:

```vhdl
when K_CMD0 =>
  if r1 = x"01" then rozkaz(K_CMD8);
  elsif proby_l = 10 then blad_ust(2);
  else proby_l <= proby_l + 1; rozkaz(K_CMD0); end if;
when K_CMD8 =>
  if r1 = x"01" and ext(11 downto 0) = x"1AA" then proby_l <= 0; rozkaz(K_CMD55);
  else blad_ust(3); end if;
when K_CMD55 =>
  if r1 = x"01" or r1 = x"00" then rozkaz(K_ACMD41); else blad_ust(4); end if;
when K_ACMD41 =>
  if r1 = x"00" then rozkaz(K_CMD58);
  elsif r1 = x"01" and proby_l /= PROBY then proby_l <= proby_l + 1; rozkaz(K_CMD55);
  else blad_ust(5); end if;
when K_CMD58 =>
  if r1 = x"00" and ext(31) = '1' then
    hc <= ext(30);                                    -- CCS: 1 = SDHC/SDXC
    if ext(30) = '1' then szybko <= '1'; got <= '1'; p <= P_GOTOWY;
    else rozkaz(K_CMD16); end if;
  else
    blad_ust(6);
  end if;
```

## Kod: Verilog

[hdl/verilog/sd_spi.v](hdl/verilog/sd_spi.v) — CRC7 rozkazu i argumenty (adres bloku zależny od typu karty):

```verilog
function [6:0] crc7(input [39:0] d);
    integer i;
    reg fb;
    begin
        crc7 = 7'd0;
        for (i = 39; i >= 0; i = i - 1) begin
            fb   = d[i] ^ crc7[6];
            crc7 = {crc7[5:0], 1'b0} ^ (fb ? 7'h09 : 7'h00);     // x^7 + x^3 + 1
        end
    end
endfunction

K_CMD8:   argument = 32'h0000_01AA;
K_ACMD41: argument = 32'h4000_0000;           // HCS: host obsługuje SDHC
K_CMD16:  argument = 32'd512;
K_CMD17:  argument = hc ? b : {b[22:0], 9'd0};  // SDHC: numer bloku; SDSC: bajty
```

## Co powstaje po syntezie

`sd_spi` (Yosys, LUT4): **568 LUT4, 201 przerzutników**, głębokość 8 — automat, rejestr rozkazu 48 b, CRC7 (kombinacyjnie z 40 bitów — największa część logiki), CRC16 bajtowo, liczniki prób i bajtów, dwa dzielniki zegara. Bufor bloku nie jest częścią kontrolera — dane płyną strumieniem; moduł nadrzędny zapisuje je do M9K albo przetwarza w locie.

## Weryfikacja

`tb_sd` (Icarus, Verilator, GHDL) z modelem karty w trybie SPI (CRC7 sprawdzane dla każdego rozkazu, NCR, echo CMD8, ACMD41 zajęta przez 3 próby, OCR, CMD16, CMD17 z oczekiwaniem, tokenem, wzorem danych i CRC16), dwie karty: SDHC i SDSC. Wynik:

- **SDHC**: inicjalizacja **2,37 ms**, 11 rozkazów (CMD0, CMD8, 4 × CMD55 + ACMD41, CMD58), sdhc = 1, kod błędu 0,
- **SDSC**: inicjalizacja **2,55 ms**, 12 rozkazów (+ CMD16), sdhc = 0,
- obie: **80 taktów SCLK** z CS = 1 przed CMD0, **0** za szybkich taktów w inicjalizacji, **0** złych CRC7,
- bloki 5 i 1000 (adresowanie bloków dla SDHC, bajtów dla SDSC): 512 bajtów, **0 błędów, CRC16 zgodne**.

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| ≥ 74 takty z CS = 1, SCLK 100–400 kHz do końca inicjalizacji, potem do 25 MHz | start karty |
| CMD0 → CMD8 (0x1AA) → CMD55+ACMD41 (HCS) do R1 = 0 → CMD58 (CCS) [→ CMD16] | inicjalizacja SPI |
| SDHC/SDXC: adres = numer bloku; SDSC: adres w bajtach | CMD17/CMD24 |
| Rozkaz 48 b z CRC7 (x⁷+x³+1); dane: token 0xFE + 512 B + CRC16 (CCITT) | ramki |
| ACMD41 do ~1 s, odczyt do ~100 ms, zapis do ~250 ms (zajętość) | limity czasu |
| Blok 0: MBR/sektor rozruchowy, sygnatura 0x55 0xAA w bajtach 510–511 | system plików |

## Typowe pułapki

- **Za szybki zegar w inicjalizacji** — część kart odpowiada, część nie („działa z moją kartą”).
- **Brak 74 taktów albo MOSI = 0 przed CMD0** — karta nie wchodzi w tryb SPI.
- **Złe CRC dla CMD0/CMD8** — w trybie SPI te dwa są sprawdzane zawsze.
- **Adres w bajtach dla SDHC albo numer bloku dla SDSC** — czytane są złe dane, bez żadnego błędu.
- **Zbyt krótkie limity czasu** na ACMD41, token danych i zajętość po zapisie — wolniejsze karty „czasem” nie działają.
- **MISO bez podciągania** — przy nieaktywnej karcie linia pływa; wymagany pull-up (na DECA — po stronie translatora).
- **Wiele urządzeń na SPI** — karta SD może nie zwolnić MISO po CS = 1 bez dodatkowego bajtu zegara.

## Pytania rekrutacyjne

1. **Opisz inicjalizację karty SD w trybie SPI.**

<details>
<summary>Odpowiedź</summary>

Zegar 100–400 kHz, co najmniej 74 takty z CS = 1. CMD0 z CS = 0 — karta wchodzi w tryb SPI i odpowiada R1 = 0x01. CMD8 z argumentem 0x1AA — karta v2 odsyła echo (inaczej starsza karta). Potem pętla CMD55 + ACMD41 z bitem HCS, aż R1 = 0x00 (do ok. 1 s). CMD58 odczytuje OCR: bit CCS mówi, czy to SDHC/SDXC (adresowanie blokami), czy SDSC (bajtami — wtedy jeszcze CMD16 512). Na koniec zegar w górę, do 25 MHz. W testbenchu: 11 rozkazów i 2,4 ms dla SDHC.
</details>

2. **Czym różni się adresowanie kart SDSC i SDHC i co się stanie przy pomyłce?**

<details>
<summary>Odpowiedź</summary>

SDSC (do 2 GB) przyjmuje w CMD17/CMD24 adres w bajtach, SDHC/SDXC — numer bloku 512 B. Typ rozpoznaje się po bicie CCS w OCR (CMD58). Pomyłka nie daje błędu: na SDHC adres bajtowy blok × 512 wskazuje blok 512 razy dalej (albo poza pojemnością → błąd adresu), na SDSC numer bloku czyta niewyrównany fragment z początku karty. Dlatego testbench sprawdza obie karty z blokami 5 i 1000.
</details>

3. **Dlaczego karta działa w trybie SPI z 1 linią danych, skoro ma 4, i ile się na tym traci?**

<details>
<summary>Odpowiedź</summary>

Tryb SPI jest częścią specyfikacji dla prostych hostów (mikrokontrolery): jedna linia danych w każdą stronę, prosty protokół bajtowy. Tryb natywny SD używa linii CMD i 4 linii DAT, z osobnym CRC16 na linię, i zegarów do 50 MHz (high speed) albo wyższych w UHS. SPI przy 25 MHz daje do ~3 MB/s, tryb SD 4-bitowy przy 50 MHz — 25 MB/s; do rejestracji danych z dużą szybkością potrzebny jest więc tryb natywny i odczyt/zapis wielu bloków (CMD18/CMD25).
</details>

## Zadania

1. Dodaj zapis bloku (CMD24) i rozszerz model karty o odbiór tokenu, danych i CRC16 z odpowiedzią danych i zajętością. **Kryterium zaliczenia:** zapis bloku, odczyt zwrotny zgodny, model sprawdza CRC16 danych, kontroler czeka na koniec zajętości.

2. Odczyt wielu bloków (CMD18 + CMD12) ze strumieniem do FIFO. **Kryterium zaliczenia:** 64 kolejne bloki odczytane jednym rozkazem, zgodne z modelem, czas porównany z 64 × CMD17.

3. Na DECA: odczytaj tablicę partycji z bloku 0 i sektor rozruchowy pierwszej partycji FAT32, pokaż liczbę sektorów na klaster na diodach. **Kryterium zaliczenia:** wartość zgodna z wynikiem `fsck.fat -v` (albo innego narzędzia) dla tej samej karty.
