## Po co to jest

Otwarte symulatory uruchamiają się w sekundę, działają na każdym systemie i w chmurze. Wszystkie testbenche w tej bazie są sprawdzane właśnie nimi — automatycznie, przy każdej zmianie w repozytorium. Zainstalujesz je raz i będziesz uruchamiać testy jednym poleceniem, bez otwierania Questy.

## Intuicja

Questa to ciężki, profesjonalny symulator z interfejsem graficznym — świetny do debugowania. Otwarte narzędzia są lekkie i działają z linii poleceń — świetne do szybkiego „czy to w ogóle przechodzi”. W pracy używa się obu: otwartych w automatycznej regresji, komercyjnych przy trudnych błędach i weryfikacji UVM.

## Teoria

### Który symulator do czego

| Narzędzie | Język | Co robi | W tej bazie |
|-----------|-------|---------|-------------|
| **GHDL** | VHDL (87, 93, 2008, częściowo 2019) | Kompiluje VHDL do programu wykonywalnego i symuluje | wszystkie testbenche VHDL (`--std=08`) |
| **Icarus Verilog** (`iverilog` + `vvp`) | Verilog-2005, część SystemVeriloga | Klasyczny symulator zdarzeniowy | wszystkie testbenche Verilog |
| **Verilator 5** | SystemVerilog, Verilog | Tłumaczy kod na C++ i kompiluje — bardzo szybki; od wersji 5 obsługuje opóźnienia (`#`) i `@` w testbenchach (`--timing`) oraz lint | testbenche SystemVerilog i sprawdzanie stylu |
| **Yosys** | Verilog, SystemVerilog (część) | Otwarta synteza — pokazuje schemat i liczbę zasobów | moduły 03 i 07 |
| **GTKWave**, **Surfer** | — | Przeglądarki przebiegów | [00.05](00.05-edytor-i-podglad-przebiegow-vs-code-teroshdl.md) |

⚠️ **Verilator musi być w wersji 5 lub nowszej.** Starsze wersje nie mają `--binary` ani `--timing` i nie uruchomią testbenchy SystemVerilog z tej bazy. Sprawdź: `verilator --version`.

### Linux (Ubuntu 24.04 i nowsze) — z menedżera pakietów

```bash
sudo apt update
sudo apt install ghdl iverilog verilator gtkwave python3 make git
```

Ubuntu 24.04 ma Verilatora 5.020 — wystarczy. **Ubuntu 22.04 i starsze mają Verilatora 4** — wtedy użyj OSS CAD Suite (niżej).

### Każdy system — OSS CAD Suite

[OSS CAD Suite](https://github.com/YosysHQ/oss-cad-suite-build) to jedna paczka z aktualnymi wersjami Yosys, nextpnr, GHDL, Icarus Verilog, Verilatora, GTKWave, SymbiYosys i cocotb, budowana codziennie. Nie wymaga uprawnień administratora.

**Linux i macOS:**

1. Pobierz archiwum dla swojego systemu z zakładki *Releases* (np. `oss-cad-suite-linux-x64-RRRRMMDD.tgz`, `…-darwin-arm64-…` dla Maców z procesorem Apple).
2. Rozpakuj w katalogu domowym: `tar xzf oss-cad-suite-*.tgz -C ~`.
3. Włącz środowisko w każdej nowej konsoli: `source ~/oss-cad-suite/environment` (albo dopisz tę linię do `~/.bashrc` / `~/.zshrc`).
4. macOS: przy pierwszym uruchomieniu system może blokować niepodpisane programy — README OSS CAD Suite opisuje, jak je odblokować.

**Windows:**

- **Zalecane: WSL2** (Ubuntu w Windows): `wsl --install -d Ubuntu-24.04`, a potem instalacja jak w Linuksie. Skrypty z tej bazy działają w WSL bez zmian, a Quartus może zostać zainstalowany w Windows.
- Alternatywnie: samorozpakowujący się plik `oss-cad-suite-windows-x64-….exe` z *Releases*, a potem `environment.bat` w każdej konsoli. Jeśli w wersji dla Windows brakuje GHDL, pobierz go osobno z [wydań GHDL](https://github.com/ghdl/ghdl/releases).

### Sprawdzenie instalacji

```bash
ghdl --version      # GHDL 4.x lub nowszy
iverilog -V         # Icarus Verilog version 12.x lub nowszy
verilator --version # Verilator 5.x
python3 --version   # 3.9 lub nowszy
```

### Uruchomienie testów z tej bazy

W katalogu repozytorium:

```bash
python3 tools/run_hdl_tests.py                              # wszystkie testbenche
python3 tools/run_hdl_tests.py modules/00-srodowisko-pracy  # tylko moduł 00
```

Oczekiwany wynik dla modułu 00:

```text
PASS  modules/00-srodowisko-pracy/hdl/vhdl/tb_blink.vhd
PASS  modules/00-srodowisko-pracy/hdl/verilog/tb_blink.v
PASS  modules/00-srodowisko-pracy/hdl/sv/tb_blink.sv
OK    modules/00-srodowisko-pracy/deca/blink/deca_top.sv (kompilacja)
OK    modules/00-srodowisko-pracy/deca/blink/deca_top.v (kompilacja)
OK    modules/00-srodowisko-pracy/deca/blink/deca_top.vhd (kompilacja)
```

Brakujący symulator jest zgłaszany jako `SKIP`, nie jako błąd. Zasady pisania testbenchy, które ten skrypt rozumie, opisuje [docs/STYL-KODU.md](../../docs/STYL-KODU.md#testbenche).

### Ręczne uruchomienie symulacji

Co robi skrypt pod spodem — dla każdego symulatora:

```bash
cd modules/00-srodowisko-pracy/hdl

# VHDL — GHDL: import plików, kompilacja, uruchomienie
ghdl -i --std=08 vhdl/*.vhd
ghdl -m --std=08 tb_blink
ghdl -r --std=08 tb_blink

# Verilog — Icarus: kompilacja do pliku .vvp i uruchomienie
iverilog -g2005 -o tb_blink.vvp verilog/blink.v verilog/tb_blink.v
vvp tb_blink.vvp

# SystemVerilog — Verilator: tłumaczenie do C++, kompilacja i uruchomienie
verilator --binary --timing --top-module tb_blink sv/blink.sv sv/tb_blink.sv
./obj_dir/Vtb_blink
```

## Reguły i liczby do zapamiętania

| Reguła | Kiedy obowiązuje |
|--------|------------------|
| GHDL: zawsze `--std=08` | kod VHDL w tej bazie |
| Verilator ≥ 5 (`--binary --timing`) | testbenche SystemVerilog |
| `source ~/oss-cad-suite/environment` w każdej nowej konsoli | OSS CAD Suite na Linux/macOS |
| `python3 tools/run_hdl_tests.py <katalog>` — test całego modułu | po każdej zmianie w kodzie |

## Typowe pułapki

- **Stary Verilator z systemu przesłania nowy z OSS CAD Suite** — sprawdź `which verilator`. Środowisko OSS CAD Suite musi być na początku `PATH`.
- **GHDL bez `--std=08`** — błędy przy `std.env.finish` i innych konstrukcjach VHDL-2008.
- **Icarus i SystemVerilog** — Icarus obsługuje tylko część SystemVeriloga. Kod SV w tej bazie uruchamiamy Verilatorem (i Questą), nie Icarusem.
- **Windows bez WSL** — część poleceń (np. `./obj_dir/...`, `source`) wygląda inaczej; skrypt `run_hdl_tests.py` działa, ale najprościej pracuje się w WSL2.

## Pytania rekrutacyjne

1. **Czym różni się symulator zdarzeniowy (Icarus, Questa) od Verilatora?**

<details>
<summary>Odpowiedź</summary>

Symulator zdarzeniowy przetwarza zmiany sygnałów jedna po drugiej w kolejce zdarzeń i obsługuje pełną semantykę czasu, opóźnień i stanów `X`/`Z`. Verilator tłumaczy projekt na model cyklowy w C++ — jest o rząd wielkości lub więcej szybszy, ale historycznie dwustanowy i z ograniczoną obsługą konstrukcji czysto symulacyjnych. Od wersji 5 obsługuje opóźnienia i zdarzenia w testbenchach (`--timing`).
</details>

2. **Po co w projekcie FPGA otwarte symulatory, skoro jest Questa?**

<details>
<summary>Odpowiedź</summary>

Do automatycznej regresji w CI (brak licencji na serwerach, szybki start), do szybkich testów jednostkowych, lintu (Verilator) i formalnej weryfikacji (SymbiYosys). Questa zostaje do debugowania z przebiegami, pokrycia kodu i UVM.
</details>

## Zadania

1. Zainstaluj GHDL, Icarus Verilog i Verilator 5 (z menedżera pakietów albo OSS CAD Suite). **Kryterium zaliczenia:** `python3 tools/run_hdl_tests.py modules/00-srodowisko-pracy` daje trzy `PASS` i trzy `OK`.
2. Uruchom ręcznie testbench VHDL poleceniami GHDL z tej strony. Potem wprowadź celowy błąd: w `hdl/vhdl/blink.vhd` zmień `CLK_HZ / (2 * BLINK_HZ)` na `CLK_HZ / BLINK_HZ`. Uruchom test ponownie i wyjaśnij komunikat. Na koniec cofnij zmianę (`git checkout -- hdl/vhdl/blink.vhd`).

<details>
<summary>Odpowiedź do zadania 2</summary>

Test zgłosi `zmiana stanu po 20 taktach, oczekiwano 10` i `FAIL`. Układ liczy teraz pełny okres zamiast połowy, więc dioda zmienia stan dwa razy rzadziej. Testbench liczy oczekiwaną wartość niezależnie od kodu układu (własna stała `HALF`), dlatego wykrywa błąd — gdyby korzystał z tej samej, błędnej formuły, błąd przeszedłby niezauważony. To podstawowa zasada testów samosprawdzających: model odniesienia nie może kopiować implementacji.
</details>
