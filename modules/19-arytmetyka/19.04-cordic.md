## Po co to jest

Sinus i cosinus dla generatora (NCO, mieszacz cyfrowy), obrót wektora (modulator IQ, transformacja Parka w sterowaniu silnikiem), moduł i faza sygnału zespolonego (demodulator, detektor fazy, przetwarzanie radarowe), atan2 z czujnika kąta — wszystko to są obroty w płaszczyźnie. **CORDIC** (*COordinate Rotation DIgital Computer*) liczy je **bez mnożarek**: tylko przesunięcia, dodawania i mała tablica stałych, jeden bit dokładności na iterację. Opracowany w 1959 roku dla nawigacji B-58, liczył funkcje w kalkulatorach HP-35, a w FPGA jest standardem wszędzie tam, gdzie bloków DSP brakuje albo potrzebny jest atan2.

## Intuicja

Chcemy obrócić strzałkę o 37°. Mamy tylko „gotowe” obroty: 45°, 26,6°, 14,0°, 7,1°… — każdy następny mniej więcej o połowę mniejszy. Obracamy o 45° (za dużo o 8°), wracamy o 26,6° (za mało o 18,6°), dokładamy 14,0° i 7,1°, cofamy 3,6°… — w każdym kroku w stronę celu. Po 16 krokach jesteśmy u celu z dokładnością do tysięcznych stopnia. Sztuczka polega na wyborze kątów: tg(kąt) = 2⁻ⁱ, więc obrót sprowadza się do przesunięcia bitowego.

## Teoria

### Iteracja

Obrót o kąt θ: x' = x·cos θ − y·sin θ, y' = y·cos θ + x·sin θ = cos θ · (x − y·tg θ, y + x·tg θ). Dla θᵢ = ±atan(2⁻ⁱ):

  xᵢ₊₁ = xᵢ − dᵢ·(yᵢ ≫ i), yᵢ₊₁ = yᵢ + dᵢ·(xᵢ ≫ i), zᵢ₊₁ = zᵢ − dᵢ·atan(2⁻ⁱ), dᵢ = ±1

Pominięty czynnik cos θᵢ daje stałe **wzmocnienie** K = Π √(1 + 2⁻²ⁱ) → **1,646760…** (dla N ≥ 10 praktycznie stałe). Kompensuje się je raz: na wejściu (x₀ = A/K) albo na wyjściu jednym mnożeniem.

### Tryby

| Tryb | Kierunek dᵢ | Wynik po N iteracjach | Zastosowanie |
|---|---|---|---|
| obrót (*rotation*) | znak reszty kąta zᵢ | (x, y) obrócony o z₀, z → 0 | sin, cos (x₀ = A/K, y₀ = 0), obrót IQ, NCO |
| wektorowanie (*vectoring*) | przeciwny do znaku yᵢ | x = K·√(x₀² + y₀²), z = z₀ + atan2(y₀, x₀), y → 0 | moduł, faza, kartezjańskie → biegunowe |

Z tymi samymi przesunięciami, ale innymi tablicami stałych, działa tryb **liniowy** (mnożenie, dzielenie) i **hiperboliczny** (sinh, cosh, eˣ, ln, √ — z powtórzeniem iteracji 4, 13, 40…).

### Zakres i dokładność

- Suma wszystkich kątów atan(2⁻ⁱ) ≈ 99,88° — sam CORDIC zbiega tylko dla |θ| < 99,9°. **Obrót wstępny o ±90°** (zamiana x ↔ y ze zmianą znaku) rozszerza zakres na cały okrąg.
- Kąt binarny: A bitów ze znakiem, 2ᴬ = pełny obrót — zawijanie kąta modulo 360° jest darmowe, a 90° to 2ᴬ⁻².
- **Każda iteracja daje ok. 1 bit**: reszta kąta po N iteracjach ≤ atan(2⁻⁽ᴺ⁻¹⁾). Dla 16-bitowego wyniku potrzeba N ≈ W + 2.
- **Bity ochronne** G ≈ log₂N w ścieżce x, y: każde przesunięcie obcina bity, a błędy się sumują; bez nich błąd rośnie z N.
- Ścieżka x, y ma 2 bity więcej (K·√2 ≈ 2,33 > 2).

### Architektury

- **Rozwinięta w potok** (`cordic`): N stopni, wynik w każdym takcie, opóźnienie N + 2, stałe przesunięcia (przewody) — tylko sumatory.
- **Iteracyjna**: jeden stopień i przesuwnik o zmiennej liczbie bitów (multiplekser), N taktów na wynik — kilkanaście razy mniej logiki.
- **Pośrednie**: kilka stopni rozwiniętych w pętli.

Alternatywa dla sin/cos: tablica ćwiartki sinusa + interpolacja ([19.06](19.06-tablice-i-aproksymacja-funkcji.md)) albo tablica + mnożarki (sin(a+b) = sin a cos b + cos a sin b). CORDIC wygrywa, gdy nie ma bloków DSP ani pamięci, gdy potrzebny jest atan2/moduł albo obrót dowolnego wektora; tablica wygrywa przy dużej przepustowości i dostępnych M9K.

## Schemat i przebiegi

```
            obrót wstępny ±90°        iteracja i (stopień potoku)                     wyjście
 x_in ─►┐                       x ─►[−/+ (y ≫ i)]─► x' ─► … ─┐
 y_in ─►├─[ćwiartka]─► x0,y0,z0 y ─►[+/− (x ≫ i)]─► y' ─► … ─┼─[zaokr. G]─► x_out, y_out (W+2 b)
 z_in ─►┘                       z ─►[−/+ atan(2^-i)]─► z' ─► …─┘             z_out (A b)
                                        ▲ dᵢ = sign(z) (obrót) albo −sign(y) (wektorowanie)
 opóźnienie: 1 + N + 1 takt; wynik w każdym takcie

 obrót o 37°: +45 − 26,57 + 14,04 + 7,13 − 3,58 + 1,79 − 0,90 + 0,45 … → 37,00° (po 8 krokach: 37,36°)
```

## Kod: VHDL

[hdl/vhdl/cordic.vhd](hdl/vhdl/cordic.vhd) — stopień iteracji; kąt `KAT` to stała z tablicy liczona w czasie elaboracji:

```vhdl
g_it : for k in 0 to N - 1 generate
  constant KAT : signed(A - 1 downto 0) := atan_a(k);
  signal d_plus : boolean;
begin
  d_plus <= z(k)(A - 1) = '0' when TRYB = 0 else y(k)(WI - 1) = '1';
  process (clk)
  begin
    if rising_edge(clk) then
      if d_plus then
        x(k + 1) <= x(k) - shift_right(y(k), k);
        y(k + 1) <= y(k) + shift_right(x(k), k);
        z(k + 1) <= z(k) - KAT;
      else
        ...
```

## Kod: Verilog

[hdl/verilog/cordic.v](hdl/verilog/cordic.v) — obrót wstępny w trybie obrotu (dwa najstarsze bity kąta to ćwiartka):

```verilog
case (z_in[A-1:A-2])
    2'b01:   begin xp <= -y0; yp <= x0;  zp <= z_in - CWIERC; end   // (90°, 180°): obrót o +90°
    2'b10:   begin xp <= y0;  yp <= -x0; zp <= z_in + CWIERC; end   // [-180°, -90°): o -90°
    default: begin xp <= x0;  yp <= y0;  zp <= z_in;          end
endcase
```

## Kod: SystemVerilog

[hdl/sv/cordic.sv](hdl/sv/cordic.sv) — tablica kątów z 32-bitowej stałej, zaokrąglona do A bitów (funkcja stała — liczona przy elaboracji):

```systemverilog
function [A-1:0] atan_a(input integer i);
    logic [32:0] t;
    begin
        t      = {1'b0, atan32(i)} + (33'd1 << (31 - A));
        atan_a = t[31 -: A];
    end
endfunction
```

## Reguły i liczby do zapamiętania

| Reguła lub liczba | Kiedy obowiązuje |
|-------------------|------------------|
| Kąty atan(2⁻ⁱ): 45°, 26,57°, 14,04°, 7,13°…; suma 99,88° | zbieżność |
| K = Π√(1 + 2⁻²ⁱ) ≈ 1,64676; kompensacja: x₀ = A/K | sin/cos |
| ~1 bit na iterację; N ≈ W + 2, G ≈ log₂N bitów ochronnych | dobór parametrów |
| Obrót wstępny ±90° → cały okrąg | zakres |
| Kąt binarny: 2ᴬ = 360°, 90° = 2ᴬ⁻², zawijanie za darmo | reprezentacja kąta |
| Obrót: dᵢ = sign(z); wektorowanie: dᵢ = −sign(y) | tryby |
| Potok: N stopni po 3 sumatory, 0 mnożarek | koszt |

## Typowe pułapki

- **Brak obrotu wstępnego** — kąty powyżej ~100° dają całkowicie błędny wynik (CORDIC „nie dojeżdża”).
- **Zapomniane wzmocnienie K** — wynik 1,647 razy za duży i przepełnienie ścieżki bez dwóch dodatkowych bitów.
- **Brak bitów ochronnych** — błąd rośnie z liczbą iteracji zamiast maleć (obcięcia przy przesunięciach).
- **Więcej iteracji niż bitów kąta** — atan(2⁻ⁱ) zaokrągla się do zera, dalsze iteracje nic nie wnoszą, a kosztują.
- **Arytmetyczne vs logiczne przesunięcie** — `>>` zamiast `>>>` (albo `shift_right` na `unsigned`) psuje liczby ujemne.

## Pytania rekrutacyjne

1. **Jak CORDIC liczy sinus bez mnożarek?**

<details>
<summary>Odpowiedź</summary>

Obraca wektor (1/K, 0) o zadany kąt serią obrotów o ±atan(2⁻ⁱ). Dzięki wyborowi kątów tg θᵢ = 2⁻ⁱ każdy obrót to przesunięcia i dodawania: x' = x ∓ (y ≫ i), y' = y ± (x ≫ i), a akumulator kąta odejmuje stałą z tablicy. Kierunek zależy od znaku reszty kąta. Pominięte czynniki cos θᵢ dają stałe wzmocnienie K ≈ 1,647, skompensowane wartością początkową. Po N iteracjach x ≈ cos θ, y ≈ sin θ z dokładnością ok. N bitów.
</details>

2. **Ile iteracji i jakie szerokości potrzebne są dla 16-bitowego sinusa?**

<details>
<summary>Odpowiedź</summary>

Ok. 1 bit na iterację, więc N ≈ 18; ścieżka x, y — 16 bitów + 2 na wzmocnienie K·√2 + log₂N ≈ 4 bity ochronne; kąt — co najmniej N + 2…4 bity, żeby atan(2⁻ᴺ) nie zaokrąglał się do zera (tu 24). Model w eksperymencie: N = 18, A = 24, G = 4 daje błąd 1,1 LSB; N = 14 — 4,5 LSB; A = 18 — 3,4 LSB.
</details>

3. **Jak policzyć moduł i fazę liczby zespolonej w FPGA?**

<details>
<summary>Odpowiedź</summary>

CORDIC w trybie wektorowania: obroty w kierunku przeciwnym do znaku y sprowadzają wektor na oś x — x końcowe = K·|v|, suma kątów = atan2(y, x). Obrót wstępny o ±90° dla x < 0 daje pełny zakres ±180°. Kompensacja K jednym mnożeniem przez 1/K (albo pominięta, jeśli moduł służy do porównań). Alternatywy: |v|² = x² + y² dwoma mnożeniami (bez pierwiastka) albo przybliżenie „alpha max + beta min”.
</details>
